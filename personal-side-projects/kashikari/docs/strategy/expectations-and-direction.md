# kashikari(貸し借り)に対する期待値・今後の方針

> HQ(楓真)からAPP-FACTORYへの方針指示。2026-09-11 受領。
> このドキュメントは方針の原文を保存したもの。運用ルールの要約は `../../CLAUDE.md` を参照。

## 1. kashikariの位置づけ

kashikariは、AI企業における最初の重要プロダクトである。

目的は単に「貸し借りを記録できるアプリ」を作ることではない。

ユーザーが、

- 誰にいくら貸したか分からない
- 誰が自分にいくら返すべきか分からない
- 旅行や飲み会の立替精算が面倒
- グループ内のお金の計算が面倒
- お金の催促が気まずい

といった問題を簡単に解決できるプロダクトを目指す。

## 2. 現在の期待値

現時点では、kashikariが大規模な市場シェアを獲得できると決めつけない。

現状は、「プロダクトとして成立する可能性がある」段階から、「実際にユーザーが継続的に使うかを検証する」段階へ移行している。

したがって、今最も重要なのは機能数ではない。以下を検証すること。

1. 本当に困っているユーザーがいるか
2. 初回利用まで到達するか
3. 友人・グループを招待するか
4. 実際の貸し借りで繰り返し使うか
5. 継続利用するか
6. Premiumに価値を感じるか
7. 口コミ・紹介が発生するか

## 3. kashikariに対する成功期待値

成功を「インストール数」だけで判断しない。段階的に判断する。

### Stage 1: 需要検証

最初の目標は、「ユーザーが本当にこの問題を解決したいと思っているか」の確認。

見る指標:

- Install
- Activation
- 初回貸し借り登録
- 初回精算
- グループ作成
- 招待
- D1/D7 Retention

### Stage 2: Product-Market Fit候補

以下が継続的に改善する場合、PMF候補として評価する。

- 継続利用
- 招待
- グループ利用
- 再利用
- オーガニック流入
- ポジティブフィードバック

特に重要なのは、「ユーザー自身が他人をkashikariに呼ぶか」である。貸し借り・精算アプリは、1人だけで完結するより複数人利用との相性が強い。したがってInvitation Loopを重要な成長要素として扱う。

## 4. APP-FACTORYに期待すること

APP-FACTORYは、「楓真から新機能を指示されるまで待つ」ことを禁止する。

kashikariの利用データ・ユーザーフィードバック・Growthデータを分析し、「今、プロダクトの最大のボトルネックは何か?」を自分で考える。

例えば、

- Install → 多い / Activation → 低い なら、「新機能追加」ではなく、オンボーディング改善を提案する。
- Install → 少ない / Activation → 高い なら、プロダクト自体よりGrowth側に問題がある可能性が高い。
- Retention → 低い なら、「なぜ2回目に使う理由がないのか」を分析する。

## 5. kashikariの長期的なプロダクト期待値

kashikariが単なる「貸し借り記録アプリ」で終わる必要はない。将来的には、

貸し借り → 立替 → 割り勘 → グループ精算 → 旅行会計 → サークル会計 → 継続的なグループのお金管理

へと利用シーンを拡張できる可能性がある。ただし、これは現時点で全部実装するという意味ではない。**ユーザーデータから需要が確認された領域のみ拡張する。**

## 6. AIの判断ルール

kashikariについて判断するとき、「競合があるから難しい」だけで終わらない。必ず、

- 市場の問題
- ユーザーの不満
- 競合との差
- kashikariの強み
- 弱み
- Growthとの相性
- 収益化可能性
- 技術コスト

を考え、「成功確率を上げるには何をすべきか」まで提案する。

## 7. 最重要原則

kashikariを成功させることは重要。しかし、「kashikariにこだわり続けること」が目的ではない。

一定期間データを取得した結果、

- 市場が小さい
- Retentionが改善しない
- Growthが成立しない
- 収益性が低い

などが明確になった場合は、改善・方向転換・縮小・撤退も選択肢としてHQに提案する。

逆に、

- Retentionが高い
- 招待が発生する
- オーガニック成長する
- 収益化できる

などの兆候があれば、kashikariへの投資を増やすことを積極的に提案する。

## 8. 最終的な期待

APP-FACTORYには、「kashikariを作ること」ではなく、「kashikariがユーザーに必要とされるプロダクトになる確率を最大化すること」を期待する。

そしてkashikariで得た技術・UX・開発ノウハウを、次のアプリへ再利用する。

kashikariは完成地点ではなく、AI App Factoryの最初の実証プロダクトである。
