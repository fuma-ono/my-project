# kashikari(貸し借り可視化アプリ)

**位置づけ**: `personal-side-projects/style-video-editor/`と同じく、オーナー個人の副業プロジェクト。会社(AI Company OS)の意思決定プロセス・凍結ルールの対象外。

## コンセプト

友達同士の「奢った/奢られた」「頼まれごとをやった/やってもらった」を記録し、誰が誰に何を貸しているかをグループで可視化するアプリ。お金だけでなく、送迎・荷物預かり等の"頼みごと"も対象にする点が、既存の割り勘アプリ(Splitwise等)との違い。詳細な検討経緯は会話ログ参照(壁打ちの結果、Setlogの「摩擦ゼロ+習慣化+友達との共同体験」という勝ちパターンを踏まえつつ、技術的難易度・法務リスクが最も低い案として選定)。

## 今回作ったもの: 動くプロトタイプ

Wizard of Oz検証ではなく、**実際に動作するプロトタイプ**を今日作って公開した。Claude Artifactsの「ライブドキュメント」機能(閲覧者の操作がそのままみんなに共有される)を使っており、専用サーバー・アカウント基盤・データベースを一切構築せずに、友達と今すぐ試せる状態になっている。

**アプリURL**: https://claude.ai/code/artifact/e6f8f8d8-6321-4b5e-9845-467ea3b85aef

ソースは `app/index.html`(単一HTMLファイル)。

### 機能

- メンバー登録(名前を追加するだけ)
- 貸し借りの記録(誰→誰、お金 or 頼みごと、内容、金額)
- 記録の精算済みマーク・削除
- 残っている貸し借りの自動集計(お金は相殺して純額表示、頼みごとは件数で表示)
- 全員が同じページを見るので、誰かが記録すると全員の画面に反映される

### 現時点の制約(検証段階として許容している範囲)

- グループ(ページ)は1つだけ。複数の友達グループを分けたい場合は、今はページを複製する運用になる
- 個人アカウント・ログインはない。URLを知っている人なら誰でも編集できる(小さな友達グループでの検証にはこれで十分)
- 通知機能はない(誰かが記録しても他のメンバーには自動で知らされない)

## UI改訂(2回目)

- 一番見たい情報(いまの貸し借り)を先頭カードに変更
- 常時表示していた入力フォームを「＋ 記録」ボタンで開閉する形に変更し圧迫感を軽減
- メンバーを色付きアバター(名前から自動生成した色+頭文字)にして、台帳・集計の両方で判別しやすくした
- 残高の各行から直接「精算する」を押せるようにした(該当ペアの未精算分をまとめて精算済みに)
- ブランド名を「カシカリ」から小文字ワードマークの「kashikari」に変更

## 本物のスマホアプリへ移行(3回目)

Web版プロトタイプで壁打ちを続ける中で、**当初からスマホアプリとしての公開を前提にしていた**ことが確認できた。また、Web版プロトタイプは「1URL=1つの共有台帳」という構造上、**招待コードもログインもなくURLを知っている人は誰でも全データにアクセスできる**という重大な制約が判明した(例: 別々の友達グループに同じURLを渡すと、お互いのプライベートな貸し借りが筒抜けになる)。

これを受けて、`mobile/`配下に**Supabase(認証+データベース+リアルタイム同期)を使った本物のExpo/React Nativeアプリ**の開発に着手した。会社の`app/`と同じ技術スタック。

- グループの作成・参加は招待コード経由。参加していないグループのデータは、UI側の制限ではなく**データベースのRow Level Securityで物理的にアクセス不能**にしてある(Web版で起きていた問題を根本解決)
- 認証はメール登録不要の匿名サインイン+表示名のみ
- Web版プロトタイプで検証したUI(残高カード・台帳・通貨選択・レシート写真添付・精算フロー)をそのまま踏襲
- 詳細なセットアップ手順(Supabaseプロジェクト作成、環境変数、EASビルド)は `mobile/README.md` を参照

**オーナーにお願いしたいこと**(`mobile/README.md`によりまとめて記載):
1. Supabaseプロジェクトの作成(無料枠)とスキーマ適用(`mobile/supabase/schema.sql`をSQL Editorで実行)
2. Anonymous Sign-Insの有効化
3. 環境変数(`.env`)の設定
4. 動作確認後、Apple Developer Program・Google Play Consoleのアカウント取得とEASビルド・提出

## Web版プロトタイプの位置づけ

`app/index.html`(Claude Artifacts版)は今後、**UI・機能のアイデア出しと素早い検証**に使う。データが分離されない制約があるため、本番の複数グループ運用には使わない。

## 技術メモ

- Web版: Claude Artifacts(`capabilities: {artifact: {}}`)。バックエンド・データベースを自前で持たず、Anthropicのホスティング基盤上で動作する
- モバイル版: Expo(React Native)+ Supabase(PostgreSQL、Auth、Realtime、Storage)
