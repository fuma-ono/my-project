# AI COMPANY OS 経営原則 v2(2026-08-11、オーナー最終承認)

AI経営パートナーの独立分析(`2026-08-11-current-state-analysis.md`への反論、`decisions/`参照)をオーナーが採用し、以下を会社運営ルールとして追加した。以後、これが最上位の経営原則になる。

## 1. 「自動化率」より「市場データ」を優先する

事業・機能・自動化の評価基準を、「どれだけ完成したか」「どれだけ自動化したか」「何コミットしたか」から、**「市場からどれだけ有効なデータを得られたか」**に変更する。市場に出せる最低限の状態になったら、それ以上の開発を続ける前に市場へ投入する。

## 2. 開発工数と市場検証のバランスを監視する

事業ごとに以下を記録する: コミット数・開発時間・市場投入数・投稿数・実ユーザー数・再生数/閲覧数・売上。**「開発工数が大きいのに市場データが少ない事業」を経営上の警戒対象とする。**(モヤスカが全コミットの32%を吸収しながら投稿0本だった実績が、この原則を導入した直接のきっかけ)

## 3. モヤスカの再定義: 「事業」ではなく「市場検証装置」

モヤスカの目的を「毎日動画を作ること」から**「完全自動化された低コストの市場検証システムを構築すること」**に変更する。GCP Cloud TTS + YouTube投稿まで完全自動化できた場合、30日間の市場検証を行い、毎日の投稿データをAIが分析して翌日の企画へ反映する。

## 4. モヤスカの14日ルール

**14日以内(2026-08-25まで)**に、GCP Cloud TTS → 動画生成 → 投稿 → 結果取得までの自動パイプラインを完成させる。完成しなければ現行iPad方式は廃止し、モヤスカを保守モードへ移行する。「あと少しだから」という理由で無期限に開発を続けない。

## 5. Shortsを現時点の有力チャネルとして扱う

実測値(Shorts 268再生 vs 長尺14〜17再生)を、成功の証明ではなく**明確な需要シグナル**として扱う。Shortsを優先的に市場検証する。ただし再生数だけで成功判断せず、視聴維持率・完視聴率・CTR・いいね率・コメント率・登録率・売上まで追跡する。

## 6. 新規事業の扱い

常設探索は停止。ただし**既存資産を使った収益化実験**は許可する。条件: 既存資産のみ・新規開発を極力行わない・新ブランドを作らない・最大2時間・1回限り。目的は「新規事業を作ること」ではなく「既存資産から新しい収益経路を発見すること」。

## 7. 「売上0」を最重要警戒状態とする

売上が¥0である限り、大規模な組織構築・大量のAIエージェント追加・高度なガバナンス・新規事業の大量探索は原則として後回しにする。最優先課題は**「市場からお金を受け取る仕組みを1つ作ること」**。

## 8. 「¥1売る」だけを目的にしない

最初の売上については、顧客・商品・支払額・購入理由・流入経路・顧客属性・継続可能性を必ず記録する。単発の¥1ではなく、**再現可能な収益モデルの最初の証拠**を取得することが目的(→ `company-os/revenue/`のスキーマに反映済み)。

## 9. 今後の経営判断ループ

すべての事業判断を **Build → Launch → Measure → Learn → Decide** のループで行う。Buildに時間をかけすぎない。市場に出してデータを取得できる状態になったら、原則として市場検証を優先する。
