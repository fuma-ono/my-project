アカウント作成ガイド

上から順番にやればOKです。名前・説明文などはそのままコピペで使える文面を用意しました。各項目右上にチェックボックスがあります。完了したらチェックしてください — ブラウザに自動保存されるので、閉じてもタブを変えても消えません(この端末のこのブラウザだけに保存されます)。

始める前に用意するもの
  • 事業用に使うメールアドレス(まとめて管理したいなら新しいGmailを1つ作るのがおすすめ)
  • SMS認証を受けられる電話番号
  • クレジットカード(Apple Developer $99/年、Google Play Console $25の支払いに必要)
  • 本人確認書類(運転免許証・マイナンバーカードなど。Apple/Googleの登録で求められる場合があります)
🔒 各アカウント、作った直後にこれだけやってください
  • 二段階認証(2FA)をその場で有効化する(あとで、にすると忘れます)
  • 使い回しのパスワードを使わない。パスワードマネージャーで生成した固有のものを設定する
  • 復旧用のメールアドレス・電話番号を最新の状態にしておく(乗っ取り対策)
  • 特にApple Developer / Google Play Consoleはアカウント停止が即事業停止につながるので、ここだけは念入りに

2b
YouTube 再設定(別アカウント)+ OAuth連携
所要時間: 約15分・専用アカウントが停止中のため必要
  1. 手順1で作った専用アカウントは利用規約違反で停止中(再審請求は提出済み)。復旧を待たず、普段お使いの別のGoogleアカウントでチャンネルを作り直す(手順2と同じ要領。チャンネル名・概要欄は上のコピーボックスを流用可)
  2. console.cloud.google.com を開き、同じGoogleアカウントで新規プロジェクトを作成(名前は任意、例: Focus Sleep Sounds)
  3. 「APIとサービス」→「ライブラリ」で YouTube Data API v3 を検索して有効化
  4. 「APIとサービス」→「OAuth同意画面」で「外部」を選び、アプリ名・自分のメールアドレスを入力。テストユーザーに自分のGoogleアカウントを追加(「テスト」モードのままでOK。Googleの審査は不要)
  5. 「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuthクライアントID」。アプリケーションの種類は必ず「テレビと限定入力デバイス」を選択(これ以外を選ぶとこの連携方式が使えません)
  6. 作成されたJSONをダウンロードし、内容をこのチャットに貼り付けてください。こちらで bgm-pipeline/credentials/client_secret.json として保存し、ログインコードの発行まで進めます(あなたはブラウザで表示された短いコードを入力して承認するだけで、パスワードはこちらに渡りません)
前回のエラー 手順5の「OAuthクライアントID作成」でエラーが出たと聞いています。エラーメッセージ(文言のスクリーンショットでも可)を教えてもらえれば、そこだけピンポイントで解決します。
これが終われば、YouTube公開の最後のブロッカーが解消します。本番サイズの動画は既に生成・検証済みなので、連携が済み次第すぐアップロードできます。

Instagram 自動投稿の設定(Meta Graph API)
所要時間: 約20分 + Appレビュー待ち2〜4週間・無料
  1. Instagramのビジネスアカウントを、Meta Business Suiteで自分のFacebookページに連携する(ページがなければ作成)
  2. developers.facebook.com/apps で新規アプリを作成(種類: 「Business」)。初回はメール認証・電話番号認証を求められる場合があります
  3. アプリの管理画面 →「アプリの設定」→「基本設定」で「アプリID」と「app secret」(「表示」をクリックしてパスワード確認)を確認し、内容をこのチャットに貼り付けてください(こちらで bgm-pipeline/credentials/meta_app.json として保存します)
  4. Graph API Explorer を開き、右上の「Meta App」で作成したアプリを選択。「Permissions」欄で instagram_business_basic・instagram_business_content_publish・pages_show_list の3つだけを検索して追加し、「Generate Access Token」を押してFacebookログイン確認を許可する
  5. 表示されたトークン(文字列)をこのチャットに貼り付けてください。長期トークンへの変換・保存はこちらで行います(instagram_auth.py import --token)
  6. アプリの「App Review」画面から、上記2つのInstagram権限のレビューを申請する(用途説明と簡単な操作動画が必要になるので、こちらで説明文案を用意します)
  7. YouTube用に作成したGoogle Cloudプロジェクトで、Cloud Storage → 「バケットを作成」。アクセス制御は「限定公開(均一)」ではなく「きめ細かい管理」を選択(これを間違えると動画を一時公開できません)。バケット名をこちらに教えてください
Appレビューが通るまでの間は手動投稿になります。審査が通り次第、YouTubeと同じように生成→自動投稿に切り替わります。

note 自動投稿の初回ログイン
所要時間: 約5分・必ずオーナー自身のPCで実行(このガイドを開いているブラウザではなく、ターミナルでの作業です)
  1. note.comには公式の投稿APIがないため、実際にログインしたブラウザセッションを自動投稿に使う方式にしています(詳細はdocs/security/checklist.mdのnote.comセクション)。以下はClaude Codeのクラウドセッションではなく、お使いのPCのターミナルで実行してください(このコンテナはnote.comへの接続がネットワークポリシーでブロックされているため、そもそも動きません)
  2. リポジトリをローカルにclone(または既にcloneしてあるフォルダ)で、note-articles/note_publish/ に移動
  3. 下のコマンドを順番に実行(初回のみ):
cd note-articles/note_publish python3 -m venv .venv .venv/bin/pip install -r requirements.txt .venv/bin/playwright install chromium .venv/bin/python note_auth.py loginクリックでコピー
  1. 最後のコマンドでブラウザが自動で開き、note.comのログイン画面が表示されます。いつも通りログインするだけです(パスワードはこのツールを一切経由しません。note.com自身のページに直接入力しています)
  2. ログインして自分のnoteホーム画面が表示されたら、開いたままのターミナルに戻ってEnterキーを押す。セッションが保存され、セットアップ完了です
未検証の注意 このクラウドセッションからはnote.comに接続できないため、投稿時のボタン名などの自動化コード(publish.py)は実地で確認できていません。初回投稿は .venv/bin/python publish.py --debug でブラウザを表示させながら試し、うまくいかない箇所があれば教えてください(その場で修正します)。
これが終われば、note記事もキュー画面からのコピペではなく自動投稿できるようになります。

課金/広告SDKの方針決定
所要時間: 決めるだけなら5分(実装はこちらで着手可能)

アプリの課金画面(PaywallScreen.tsx)は現在モックです。実際に課金を有効にするには、以下のどれにするかだけ決めてもらえれば、その方式で実装します(アカウント作成は不要、コードだけの作業です)。

選択肢A(推奨) RevenueCat を使う。App Store/Google Play双方のサブスク課金を1つのSDKで統一的に扱えるので実装が単純。無料枠(月間売上$2,500まで手数料ゼロ)があり、今の規模ならコストはかからない。RevenueCatの無料アカウント作成(app.revenuecat.com/signup)だけ必要
選択肢B expo-in-app-purchases でApple/Googleの課金APIに直接つなぐ。外部サービス依存が減るが、ストアごとに実装・テストが二重になり手間が増える
広告(任意) 無料ユーザー向けに広告を出す場合はAdMobが一般的。ただし睡眠・集中用アプリなので、広告で体験を損なうと本末転倒になりやすい。まずはサブスクのみで様子を見て、後から検討することを提案します
選択肢を教えてもらえれば、そのまま実装に着手します(ストア申請にはApple Developer / Google Play Consoleの登録が別途必要です)。

プライバシーポリシー・利用規約の記入
所要時間: 約5分
  1. docs/legal/privacy-policy.md を開き、末尾の「お問い合わせ先」欄に連絡先メールアドレスを記入
  2. docs/legal/terms-of-service.md を開き、「事業者名」「お問い合わせ先」「準拠法・管轄」の3箇所(<オーナーが記入>となっている部分)を記入
  3. 内容自体の法的な最終確認(気になる点があれば教えてください。心配であれば専門家レビューも検討事項として記録しておきます)
  4. 記入が終わったら「終わった」とだけ教えてください。App Store Connect / Google Play Consoleの該当欄に登録できる形で案内します
アプリのストア申請に必須の書類です。ドラフト自体は現状のアプリの実装(個人情報を収集しない)に基づいて作成済みです。
