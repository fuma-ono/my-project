## 1. 結論(先に)
- **公式の四半期前期比(%)の系列がある**(ONS の時系列 API、CDID **IHYQ**)。計算は要らない。
- **実装可能**。ただし既存の ONS アダプターは月次(`months`、'YYYY MON')だけを読むので、**四半期(`quarters`、'YYYY Qn')を読む拡張**が要る。
- **改定は非常に遅くまで続く**(§5)。追跡範囲は**日数ではなく直近 12 四半期**(HQ の方針。§6)。**改定の約 3 分の 1 が追跡範囲外になる可能性があり、範囲外の過去の改定は検出されない**。初回値の期限(`maxDaysAfterRelease`)とは分離し、QA-1 の状態修復の範囲は**広げない**。
- **データセット ID が公表ごとに更新先が違う**(§3)。初回値は `pn2`、改定確認は `pn2`・`qna` のうち releaseDate が新しい方。`datasetId` と公表日(ロンドン時間の日付)の照合を必須にする。
- 推奨: 導入する(優先度は中)。

## 3. データセット ID の違い(第 1 版の誤記を訂正)
同じ IHYQ が、**データセットごとに別の公表で更新される**。2026-11-18 の実測:

| データセット(`description.datasetId`) | データセットの名前(`datasetUri`) | `releaseDate`(UTC) | ロンドンの日付 | 最新の四半期 | `nextRelease` の記載 |
|---|---|---|---|---|---|
| **PN2** | secondestimateofgdp | 2026-11-12T00:00Z | 2026-11-12 | **2026 Q3 = 0.7** | 22 December 2026 |
| **QNA** | quarterlynationalaccounts | 2026-09-29T23:00Z | **2026-09-30**(BST) | 2026 Q2 = 0.5 | 12 November 2026 |
| UKEA | unitedkingdomeconomicaccounts | 2026-09-29T23:00Z | 2026-09-30 | 2026 Q2 = 0.5 | 22 December 2026 |
- **第 1 版の訂正**: 「ukea・qna は古い」は誤り。**qna と ukea は、9/30 の公表(四半期国民経済計算・UK economic accounts)で更新されたもの**で、9/30 時点では最新だった。今回 11/12 に更新されたのは `pn2` だけ。「古い」のではなく、**公表ごとに更新されるデータセットが違う**。
- 同じ四半期の値が、更新のタイミングによってデータセット間で違うことがある(例: 2026 Q2 は、8 月の pn2 で 0.4、9/30 の qna・ukea で 0.5、11/12 の pn2 で 0.5)。
- `nextRelease` の記載は、データセットごとに別の予定を指し、**更新先の予告として信用しない**(qna の「12 November 2026」は、11/12 に qna が更新されていないので、そのとおりにならなかった)。

### 3.1 取得先の設計(C の指摘)
| 用途 | 取得先 | 条件 |
|---|---|---|
| **初回値**(初回推計の日: 2027-02-12・05-14 …) | **`pn2`** | `datasetId` が `PN2`。`releaseDate` のロンドンの日付 = 予定表の公表日。最後の四半期の行の `updateDate` が公表日。対象四半期 = 予定表の referencePeriod |
| **改定確認** | `pn2` と `qna` を**両方取得**し、`releaseDate` が**新しい方**を使う | 取得した応答の `datasetId` が許可リスト `{PN2, QNA}` にあること(`UKEA` など他は使わない)。許可リストに無い・取得に失敗した方は無視し、残りだけで判断(両方失敗なら何もしない) |
- `releaseDate` は **UTC の時刻**(夏時間では前日 23:00Z)。**ロンドン時間の日付に直して**比べる(既存の `localDate(…, 'Europe/London')` と同じ)。
- 2 つの releaseDate が同じ日なら `pn2` を優先する(初回推計の日の値)。
- 許可リストを `datasetId` で検証するのは、データセットの取り違えと、URL の誤りによる別の系列・別の版の混入を防ぐため。

### 3.2 3 つのデータセットの更新タイミングの違い(過去の版の日付で確認、2026-11-18)
各データセットの `versions` の `updateDate`(= その版が次の版に置き換えられた公表の日時)の直近 9 件:

| データセット | 直近の更新日(UTC の日付) | 読み取れるタイミング |
|---|---|---|
| **pn2** | 2025-02-13、05-15、08-14、11-13、2026-02-12、05-14、08-13、**11-12** | **初回の四半期推計の日**(2・5・8・11 月)だけ。四半期国民経済計算の日(3・6・9・12 月)には更新されていない |
| **qna** | 2025-03-28、06-30、09-30、12-22、2026-03-31、06-30、**09-30** | **四半期国民経済計算の日**(3・6・9・12 月)。初回推計の日には更新されていない |
| **ukea** | 2025-03-28、06-30、09-30、12-22、2026-03-31、06-30、**09-30** | qna と同じ日 |
- 結論: **pn2 = 初回の四半期推計(Feb/May/Aug/Nov)、qna・ukea = 四半期国民経済計算(Mar/Jun/Sep/Dec)**。同じ四半期の値は、この 2 種類の公表で別々に改定される。
- したがって、**改定確認には pn2 と qna の両方を見て、releaseDate が新しい方を使う**(§3.1)。初回推計の日の直後は pn2、四半期国民経済計算の日の直後は qna が新しい。
- `ukea` は、qna と同じ日に更新され、内容も同じ四半期の値(2026-11-18 の実測で 2026 Q2 = 0.5 が一致)なので、**許可リストに入れる必要はない**(qna で足りる)。

### 4.1 12/22 公表後の確認手順(12/23 に実施する、調査のみ)
12/22 の公表が、どのデータセットを更新するかを、実 API で確認する。**実装の最終判断の前提**。

1. **取得**: 次の 3 つを取得する。
   - `…/timeseries/ihyq/pn2/data`
   - `…/timeseries/ihyq/qna/data`
   - `…/timeseries/ihyq/ukea/data`
2. **各応答で読む**: `description.datasetId`、`description.releaseDate`(**ロンドンの日付に直す**)、`description.nextRelease`、`quarters` の末尾 3 行(`value`・`updateDate`)、`versions` の件数と最後の `label`・`updateDate`。
3. **確認する点**:
   - [ ] `qna`・`ukea` の releaseDate が **2026-12-22**(ロンドン)になっている。
   - [ ] **2026 Q3 の値**: qna・ukea での値(改定の有無)と、pn2 の 0.7 との差。
   - [ ] **`versions` の件数**が、各データセットで増えた(qna は 44 → 45、ukea は 43 → 44 の見込み)。増えていなければ、更新されていない。
   - [ ] **`pn2` が 2026-11-12 のまま**か(releaseDate・versions が変わっていないか)。**過去の版の日付(§3.2)からは、pn2 は 12/22 に更新されない見込み**。変わっていれば、§3.1・§3.2 の「pn2 は初回推計の日だけ」の前提を直す(ただし pn2 の `nextRelease` には「22 December 2026」とあり、これだけが逆の兆候)。
4. **判断**: 上の結果で、**改定確認に `pn2`・`qna` のどちらが最新になるか**が分かる。許可リスト `{PN2, QNA}` の方針(§3.1)が妥当かを確認し、本書に結果を追記する。
5. 取得は読み取りだけ(書き込みなし)。

## 5. 改定履歴と改定頻度(実測)
### 5.1 versions の読み方(注意)
- 系列ページの `versions` 配列は **47 要素**だが、**`v15` が 2 回載っている**(同じ `uri`・同じ `updateDate` 2019-05-10)。**ラベルの重複を除くと v1〜v46 の 46 版**。
- 各 `vN` の `updateDate` は、**その版を次の版に置き換えた公表の日時**を指す(例: v46 = 2026-11-12。`/previous/v46/data` の中身は 2026-08-12 公表のデータ)。**現行版(`…/ihyq/pn2/data`、2026-11-12 公表)は `versions` に載らない**。`/previous/v47/data` は存在しない(404)。したがって、**データ点は過去版 46 + 現行 1 = 47**。
- v16(2019-05-10T08:59:07Z)は、v15 の約 30 分後の版(同日)。**原因は未確認**。
- 実装で版を数える・一覧するときは、**ラベルの重複を除く**こと。

### 5.2 改定の実測(D の再集計)
**方法**: IHYQ の pn2 の 47 データ点(過去版 v1〜v46 と現行)を、公表日(`description.releaseDate`)の順に並べ、各四半期について、**「最初に現れた版の公表日」から、「値が前の版と違った版の公表日」までの日数**を数えた。四半期を、**ある版で最新の四半期として初めて現れたもの(46 四半期)**に限った。

| 指標 | 値 |
|---|---|
| 対象の四半期 | 46 |
| 改定の件数 | 204(1 四半期あたり平均 約 4.4 回) |
| 改定の日数の中央値 | 456 日 |
| **270 日を超える改定の割合** | **76%** |
| 365 日 / 730 日 / 1,095 日 / 1,460 日 を超える割合 | 59% / 39% / 29% / 23% |
| **1,700 日を超える割合** | **19%**(18.6%) |
| **最長** | **3,458 日**(2016 Q1: 0.4 → 0.5 が 2026 年に改定) |
- **C の集計**(270 日超の改定が 64%、最長 1,645 日)と、**D の再集計(76%、最長 3,458 日)は、定義の違いで数が合わない**(C の定義の詳細は未確認。四半期の範囲・版の範囲が違う可能性)。**どちらでも、改定は 1 年以上後にも頻繁に入る**という結論は同じ。
- **長期の改定の主因は、毎年の大規模な改定(ONS の Blue Book、毎年 9 月の四半期国民経済計算)**とみられる。過去数年分が一度に動く。
- 最近の例(実 API の版): 2025 Q4 は 0.1(2026-02)→ 0.2(05 月)→ 0.1(08 月)→ **0.0(2026-11)**。2026 Q2 は 0.4(2026-08)→ **0.5(2026-11)**。

## 6. 改定確認の追跡範囲(採用方針: 「直近 N 件」方式)
HQ の方針(2026-11-18)により、**日数ではなく、直近 N 件のイベント**で追跡範囲を決める。1,700 日の固定案は採用しない。

| 指標 | 追跡範囲(採用方針) |
|---|---|
| **GB_GDP_QOQ**(本書の対象) | **直近 12 四半期**(約 3 年) |
| GB_GDP_MOM(既存。月次 GDP) | 直近 36 か月(約 3 年。現在の 56 日方式から置き換え) |

### 6.1 `latestEvents` の定義(C の指摘で修正)
「直近 N 件」= **その指標の、次の 3 つの条件をすべて満たすイベントを、公表日時の新しい順に N 件**。
1. **DB に `economic_events` の行が存在する**(公表予定表の行ではない)。
2. **RELEASE のスナップショットが存在する**(初回値が保存済み)。
3. 公表日時が現在以前で、取りやめ(CANCELLED)ではない。
- **指標ごとに数える**(同じ provider の他の指標を含めない)。**公表予定表の行数では数えない**(予定表には、イベント未作成の回・未来の回・取りやめの回が含まれる)。
- 例: 予定表に 20 行あっても、DB に 12 件、うち RELEASE が有るのが 5 件なら、N = 12 でも対象は 5 件。
- 設定の形・検証(`days` と `latestEvents` は排他、`days` は 1〜3,650、`latestEvents` は 1〜200 の整数。0 以下は拒否)は、`claude/fx-indicator-research-d` の `03-revision-lookback-per-indicator-design.md`(第 4 版)§3.3。

### 6.2 追跡範囲の限界(明記)
- **改定の約 3 分の 1 が、追跡範囲外になる可能性がある**。D の実測(§5.2、204 回の改定)で、**12 四半期(約 3 年 = 1,095 日)を超える改定が 29%**。C の集計でも同程度。月次 GDP の 36 か月は、過去の版の集計をしていない。
- **追跡範囲外の過去の改定は、検出されない**。`event_revisions` に入らない。
- **追跡範囲外の値は、「最新の公式値」と断定しない**:
  - **初回値** = `RELEASE` スナップショット(不変。初回推計の公表日の値)。**初回値と後の値の区別は維持**する。
  - **追跡範囲内**: `event_revisions` の最後の ACTUAL =「最後に確認した公式値」。
  - **追跡範囲外**: 「最後に確認した値(確認時点のもの)」。**現在の ONS の値と一致するとは限らない**。画面・API・文書で「最新」と表記しない。
  - 確認した日付の列は現在の `event_revisions` に**無い**(DB 変更の要望として記録。`03` §9)。
- **初回値の期限とは分離**: `GB_GDP_QOQ` の `maxDaysAfterRelease` は **7 日**と明示。追跡範囲を変えても、初回値として受け付ける範囲は変わらない。ONS のパーサーは、API の公表日と予定の公表日の一致も要求する。
- **QA-1 の状態修復の範囲は広げない**: 修復は `repairLookbackDays`(既定 90 日)だけで決まり、ソースごとの追跡範囲(12 件・36 件)を**参照しない**。

### 6.3 追跡範囲外の確認(年 1 回、dry-run)
- **時期**: 毎年 **11 月の初回推計の後**(英国 GDP の第 3 四半期の初回推計は 11 月中旬)。
- **手順**:
  1. **指標を限定して実行**(`--indicators GB_GDP_QOQ,GB_GDP_MOM`)。他の指標のソースは処理しない(API・DB の呼び出しは、対象の指標だけ)。
  2. **深い窓**(`--revision-latest-events 60` など、範囲外まで含める)+ **`--dry-run`**(書き込みなし)。
  3. 範囲の内/外の件数、**範囲外で値が違うイベントの件数・最大の差・最も古い日付**を報告する。
- **書き込みを伴う深い確認は、HQ の承認後**。dry-run の結果を見てから、範囲を広げるか判断する。
- 実行は、今は手動(`workflow_dispatch`)。**定時実行は、承認・実装されるまで前提にしない**。

### 6.4 費用・処理件数・保存履歴(12 件・36 件の評価)
| 項目 | 評価 |
|---|---|
| 対象イベント数 | QoQ 最大 12。導入直後(2027-02-12 以降)は 1〜2 件から増える。MoM は最大 36(§6.1 の 3 条件を満たすイベントだけ) |
| 公式 API の呼び出し | **変わらない**: 同じ応答(§3.1 の `pn2`・`qna` の各 1 回)を、全イベントで使う |
| DB の問い合わせ | イベントごとに `getReleaseSnapshot`・`latestRevisionValues` の 2 回。QoQ 最大 24 回、MoM 最大 72 回/実行。**実行は手動**なので、頻度は人の運用次第。負荷は小さい |
| 保存履歴(`event_revisions`) | **値が変わったときだけ**書く。1 回の公表で数件、9 月は多い。年に数十行 |

## 7. 取得 API・形式
- JSON(ONS の `…/data`)。鍵なし。`quarters` 配列(`date` = '2026 Q3'、`value`、`updateDate`、`sourceDataset`)。月次は `months`。
- `updateDate` は、値が変わらなくても公表日に更新される(2025 Q4 の行も 2026-11-12)ので、**改定の検知には使えない**(値の比較が必要)。初回値の確認には使える。

## 8. 既存基盤との適合性
| 項目 | 評価 |
|---|---|
| 取得・照合 | `parseOnsValueForRelease` とほぼ同じ。**`quarters` と 'YYYY Qn' を読む分岐**、`datasetId` の許可リスト、2 つのデータセットの取得(改定確認)が必要 |
| 公表予定 | `gbAuCaSchedule.ts` に初回推計の回(2027-02-12・05-14)を追加。referencePeriod は題名の月から 'YYYY-Qn'(October to December = Q4) |
| 初回値の保存 | 既存の official-values(公表日・対象期間の一致、数値・単位・出典) |
