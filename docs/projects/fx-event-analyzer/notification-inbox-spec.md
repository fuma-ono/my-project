# FX Event Analyzer: アプリ内通知一覧の仕様

**出典**: HQ指示(2026-10-13)「おすすめの通知仕様」。通知一覧画面(ホームの通知ベル → `NotificationListView`)の、保存期間・既読・重複・プッシュ通知との関係を決める。

## 1. 保存期間と既読後の扱い

| 通知の種類 | 保存期間 | 既読後の扱い |
|---|---|---|
| 経済指標 | 30日 | 保存期間内は残す |
| 要人発言 | 30日 | 保存期間内は残す |
| レートアラート | 7日 | 保存期間内は残す |
| カレンダー更新 | 7日 | 保存期間内は残す |
| システム通知 | 30日 | 保存期間内は残す |

- 保存期間は初期案。期限を過ぎた通知は一覧から自動的に外す。
- レートアラートとカレンダー更新の通知はまだ無い。足すときにこの保存期間で入れる。

## 2. 古い通知は自動で外す

- 保存期間を過ぎた通知は一覧から外す。
- **アプリ(実装済み 2026-10-13)**: 届いた通知を受け取ったとき(`NotificationsStore.record`)と、通知一覧を開いたとき(`pruneExpired`)に外す。一覧は表示のたびに期限で絞り込む。
- **サーバー(設計のみ・未実装)**: 下の「6. サーバー側の設計案」のとおり、期限をサーバーでも持てる形にする。

## 3. 同じイベントの通知を重複させない

- 「発表5分前」と「発表時」のように、通知の種類(何分前か)が違うものは別々に残す。
- 同じイベント・同じ通知の種類は1件だけにする。
- アプリでは `NotificationEntry.targetKey` を「種類(経済指標/要人発言)・イベントID・何分前か」で作る。

## 4. 通知一覧とプッシュ通知は分ける

- 端末に届くプッシュ通知(通知センター)を消しても、アプリ内の通知一覧の既読・保存には影響させない。
- アプリ内の一覧は端末の記録(`NotificationsStore`)として、通知センターとは別に持つ。

## 5. 通知一覧の画面

- **上部**:
  - 左に「● 未読 N件」。
  - 右に「すべて既読」と、並び替え(新しい順/古い順)。
- **既読になるとき**: 行を開いたときに、その1件が既読になる。「すべて既読」で全部が既読になる。
- 画面を開いただけでは既読にしない。

## 6. サーバー側の設計案(未実装)

ログインした端末どうしで既読をそろえたり、サーバーで期限を管理したりするときの形。

- **テーブル `notification_inbox`**:

  | 列 | 内容 |
  |---|---|
  | `id` | 主キー |
  | `user_id` | 利用者 |
  | `kind` | INDICATOR / SPEECH / RATE_ALERT / CALENDAR_UPDATE / SYSTEM |
  | `target_id` | イベントIDなど |
  | `trigger` | 例: `LEAD_5`、`AT_RELEASE` |
  | `title` | 見出し |
  | `body` | 本文 |
  | `notify_at` | 通知の時刻 |
  | `read_at` | 既読にした時刻(未読は null) |
  | `expires_at` | `notify_at` + 種類ごとの保存期間 |

- **重複防止**: 一意制約 `(user_id, kind, target_id, trigger)` で同じ通知の二重配信を防ぐ。
- **期限切れの削除**: 1日1回のジョブで `expires_at < now()` の行を消す。一覧のAPIも `expires_at > now()` だけを返す。
- **API**:
  - `GET /notifications`: 並び順を指定できる。未読件数も返す。
  - `POST /notifications/{id}/read`: 1件を既読にする。
  - `POST /notifications/read-all`: すべて既読にする。
- **プッシュ通知との関係**: プッシュ通知の配信記録とは別のテーブルにする。プッシュを消しても `notification_inbox` は変わらない。
