## 構成の型(台本を書く時のテンプレート)

**2026-08-17改訂: 冒頭3秒重視。** オーナーが`final_v6.mp4`(台本01)を実際に視聴してレビューした結果、「映像・演出は投稿可能品質だが、初見ユーザーを最初の数秒で止める力が弱い」と判定(総合55〜60点、冒頭の引き4/10)。原因は「今日も朝から掃除よ」のような**普通の会話から始める構成**そのものにあると特定された。台本01〜05はこの旧構成のまま(作り直さない — 「1本を完璧にする」のではなく投稿してデータを取る方針のため)。**06以降の新規台本から、以下の新構成を適用する。**

1. **フック(0〜3秒)**: 結末の一部・強い一文を先出しする。「普通の会話から始めない」のが最重要ルール。
   例:「3年間家事を一度もやらなかった俺が、今日母にこれを見せた。」
   **2026-08-18: オーナー指示「これからフックはなくていい」を受け、`フック:`
   行(テキストによる先出し)は台本06以降廃止**(01〜05は変更なし)。
   「普通の会話から始めない」という狙い自体は生きているが、その役目を
   テキストではなく**冒頭に差し込むAI画像**(検討中、下記参照)に譲る想定。
   画像の目処が立つまでは、単に1行目から会話を始める(旧構成寄り)に戻る。
2. **状況説明・違和感(3〜10秒)**: 関係性とモヤモヤの原因を提示(誰が・何を・どれくらいの期間)
3. **情報開示(10〜40秒)**: 具体的な理不尽エピソードを重ねながら、1.のフックの伏線を回収する形で情報を小出しにする
4. **感情の反転(40〜55秒)**: 証拠・記録・数字など、相手の顔色が変わる決定的な事実
5. **余韻(55〜65秒)**: 意外な一言/価値観の反転/次の展開を想像させる一言/コメントを誘う問い、のいずれか。**毎回無理に「続き」を匂わせる必要はない** — 「感情的な余韻で終わる」パターンと「次回を期待させる」パターンの両方をExperimentする
6. **フィクション表記**: 「（この物語はフィクションです）」で締める(変更なし)

台本ごとに次の2つを記録する(下記「冒頭タイプ分類」と「生成時セルフチェック」、Experiment記録は`docs/company-os/experiments/moyasuka-<話数>-<slug>.json`に転記):

**冒頭タイプ分類**(どれを採用したか記録し、10〜30本のExperimentで勝ちパターンを探す):
- A: 普通の会話から開始(旧構成。今後は非推奨だが比較のため使うこともある)
- B: 衝撃的な一文から開始
- C: 結末の一部を先出し
- D: 数字・証拠を先出し
- E: 質問形式
- F: 「実は〜」形式

**生成時セルフチェック**(台本を確定する前に自問し、弱ければ冒頭を書き直す):
1. 冒頭3秒に強いフックがあるか
2. 初見ユーザーが続きを見る理由が明確か
3. 中盤で情報が小出しに開示されているか(全部を冒頭で明かしていないか、逆に何も引っかかりを作れていないか)
4. 感情が反転するポイントがあるか
5. 最後に余韻(または続きへの引き)があるか

尺の目安: 60秒Shorts想定で400〜550字程度(`scripts/01-sample.md`が約480字)。参考動画([嫁のクイズに答え続けた旦那の逆襲ｗｗ](https://youtube.com/shorts/khhWR7N1LaM)、この分野の実例チャンネル「[笑うバナナLINE](https://youtube.com/channel/UCzpzhbRBG_bXjmtetyRw9qQ)」・登録者15.3万人)をAPIで確認したところ、実際の尺は`PT1M`(ちょうど60秒)。この尺目安は妥当と確認できた。

## タイトルの型(2026-08-06、参考動画で確認)

上記参考動画のタイトル「嫁のクイズに答え続けた旦那の逆襲ｗｗ」に倣い、以下の型で統一する:

- 説明的な一文にしない。短く、状況+結果だけを提示
- 文末は「ｗｗ」(全角w2つ)で締める(このジャンルの定番。深刻すぎない・エンタメとして消費しやすいトーンを示す記号として機能)
- 「逆襲」「返り討ち」のような一語のフック表現を積極的に使う

現在の3本のタイトル案もこの型に修正済み:
- 01: 「家事は全部私」と言い張る義母、証拠を見せた結果ｗｗ
- 02: マウント全開のママ友に一言返したらｗｗ
- 03: 企画を横取りした同僚、日付ひとつで返り討ちｗｗ

**2026-08-18追記**: オーナー指示「毎回タイトルに絵文字をつけるようにして」を受け、
実際に公開されるタイトルには🤣を自動付与する(`moyasuka/publish.py`の
`TITLE_EMOJI`/`_title_from_script()`で機械的に付与、上記スクリプト内の
`**タイトル案**:`行そのものは書き換えない)。「ｗｗ」で締める型と相性が
いいのでこの絵文字を標準にしたが、台本によって変えたい場合は同関数で分岐可能。

## キャスト運用

VOICEVOXキャラクターを役割で固定し、視聴者が「この声=この役」と学習できるようにする(認知コストを下げる、シリーズものの定石):

- 若い女性主人公(嫁・部下・後輩役): ずんだもん
- 年上の女性・主な敵役(義母・ママ友・上司役): 四国めたん
- 男性・主な相手役(夫・同僚役): 玄野武宏
- 第三者・女性の証人役(叔母・義姉・別のママ友役): 春日部つむぎ
- 第三者・男性の証人役(先輩役): 白上虎太郎

これはサンプル台本(`scripts/01-sample.md`)の配役をそのままシリーズ標準にする決定。オーナー確認事項ではなく、一貫性のための実務上の決定として社長判断で固定。

**2026-08-06追記**: 「もっとスカッとさせる」フィードバック対応で各台本に複数の第三者(叔母/義姉、別のママ友、先輩)を追加投入した結果、当初の3声固定のままだと同じシーンに出てくる別々の女性キャラ(義母×叔母/義姉)・男性キャラ(同僚×先輩)が同じ声になり視聴者が聞き分けられなくなる問題が判明。第三者・証人役として春日部つむぎ(女性)・白上虎太郎(男性)を追加し5声固定に拡張した。白上虎太郎のstyle idは実エンジンでの確認優先度が他より高いとコード側(`moyasuka/voicevox_narrate.py`)にコメントで明記している。実際の合成手順は`docs/projects/moyasuka/voicevox-setup.md`参照。

(参考: 「笑うバナナLINE」は白上虎太郎・四国めたん・玄野武宏・春日部つむぎ等7種のVOICEVOXキャラを動画ごとに使い分けている。うちは視聴者の認知コストを下げる狙いで役割固定にしており、この方針は変更しない)

**2026-08-18追記(若者向け台本06〜10での役割解釈)**: 上記は「義母/旦那」等
特定の続柄を前提にした説明だが、声そのものは続柄ではなく**役割の型**

## 背景タイプ(2026-08-17追加)

`final_v6.mp4`の海の背景(`background_gen.py`)自体は品質上の問題なしと評価されたが、ストーリーとの関連性が弱いと指摘された。今後は台本の感情・状況に合わせて背景タイプを選ぶ(候補: 海/雨/夜の街/電車/車窓/カフェ/部屋/住宅街/夜道)。**ただし背景生成システムの大改修はしない** — まずは既存の`ocean_glitter_01.png`のような写真を状況に合う別の1枚に差し替える程度の運用で様子を見る。台本のExperiment記録(`background_type`フィールド)に使った背景タイプを残し、どの組み合わせが再生数に効くかは他の変数と同様にデータで判断する。

## 主人公(嫁役等)の名前の付け方(2026-08-14追加)

**「○○さん」のような伏字プレースホルダーは禁止。** 第三者が主人公を名前で呼ぶセリフ(証拠提示シーンでの「え、全部○○さんがやってたの?」等)で使うと不自然なため、以下の固定名プールから毎回1つ選んで使う:

- 美咲 / 翔太 / 和子 / 真由 / 恵子

台本を手動で書く場合は文脈に合う名前を1つ選ぶ(嫁役なら美咲・真由・恵子等の女性名、性別が変わる役なら翔太等)。将来、台本生成を自動化するRoutineを作る場合は、この5つからランダムに選ぶロジックを組み込むこと(名前の重複や偏りを避けるため、直近数本で使った名前を除外する程度の工夫はしてよいが、大掛かりな仕組みは不要)。
