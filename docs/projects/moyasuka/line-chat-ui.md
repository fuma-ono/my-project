# LINEチャットUI化(モヤスカ)

オーナー指示(2026-08-06)「ラインのようなやり取りにして」を受けて、動画の見せ方を作り直した。同日中に2回、実際の映像を見たオーナーからの追加フィードバックで調整を重ねている。

## v1: 字幕方式 → LINEチャット方式へ

それまでの`assemble_video.py`は、台本の地の文をそのまま白文字の字幕として画面下に焼き込んでいた。チャンネルのコンセプトは「LINE風の会話ドラマ」なのに、実際の映像は普通のナレーション動画になっていた——見せ方のズレだった。

`moyasuka/line_chat.py`を新設し、台本そのものをLINEのメッセージのやり取り(誰が・何を送ったか)として書き、実際のチャット画面のように吹き出しが1通ずつ流れてくる映像に作り直した。

## v2: メッセージをコンパクトに、連投をグループ化

オーナー:「文章をもう少しコンパクトに、チャット風だから」

- 1メッセージ1〜2文だった台本を、実際のLINEのように短文を連続送信する形に書き直し
- 実装してみると、短文化で同一話者の連続メッセージが増え、そのたびに名前・アイコンが繰り返し出るのが不自然だったため、連投では最初の1通だけに表示する仕様に変更(実際のLINEの「連投」表示と同じ)

## v3: 内容を面白く・1分尺に、ナレーションカード廃止、パネルを縮小して上に

オーナー:「話が面白くないし、短い。ショート動画用に1分動画にして。あと後ろのボールが見えないからもう少しチャット画面は小さく、そして、上にして、心の声とかいらない」

4点まとめて対応:

1. **尺を1分に**: 台本を29ターンに増量(以前は17ターン、約41秒)。ただ長くするのではなく、後述の内容強化と合わせて実質的な情報量を増やした結果として尺を伸ばした
2. **内容を面白く**: 具体的な数字(掃除613回・洗濯890回・料理1200回)を出す「証拠」の見せ方を強化し、第三者(叔母)が会話に途中参加して驚く反応を追加。第三者の反応が入ることで「まわりも味方する」スカッと感が増す、という定番の型を踏襲
3. **ナレーションカード廃止**: 状況説明の`> テキスト`カードを全廃。物語は完全にキャラクターが実際に打った発言だけで進むように書き直した。「心の声」的な地の文はゼロ。`parse_chat_script`のパース機能自体は残してある(将来また使う可能性のための後方互換)が、台本では使用しない
4. **チャットパネルを縮小し、上部に配置**: パネルを画面下端まで伸びる「ボトムシート」から、画面上部に浮かぶ固定高さの「カード」に変更(角丸を四隅すべてに)。空いた下部の広いスペースをボール背景に譲った

### レイアウト変更の詳細

| 項目 | v1〜v2 | v3 |
|---|---|---|
| パネル位置 | `PANEL_TOP=360`〜画面下端(920px) | `PANEL_TOP=50`〜`PANEL_BOTTOM=700`(650px) |
| 角丸 | 上2つのみ(ボトムシート) | 四隅すべて(浮かぶカード) |
| ボール背景の可視範囲 | 上部360pxのみ(ほぼアーチの先端しか見えない) | 下部580px(700〜1280)、アリーナ全体が収まる |

`background_gen.py`のアリーナ位置(`ARENA_CY`)も`H*0.42`→`H*0.77`に、半径も300→230に変更し、パネル下の広い空間にちょうど収まるよう再調整した(ボールのスピード・サイズも比率を保つよう調整)。この位置決めはLINEチャットUIのレイアウトに合わせたもので、背景映像パイプライン自体の設計判断(v1〜v4の反復)を覆すものではない。

## 画面構成(720x1280、確定版)

- **上部(50〜700px)**: 白い浮かぶチャットカード。上端にLINE風の緑ヘッダーバー(グループ名表示)、その下にメッセージがスクロール表示される
  - 自分(「私」)の発言 → 緑の吹き出し、右寄せ
  - 相手の発言 → 白い吹き出し、左寄せ。同一話者の連投は最初の1通だけ名前・アイコン表示、間隔を詰める
- **下部(700〜1280px)**: ボール背景がフル表示。円形アリーナ内で物理演算バウンドする吹き出し型のボールが、数を増減させながら動き続ける

## 台本フォーマット(scripts/*.md)

`---`より下を以下のルールでパース:

- `グループ名: ◯◯` → ヘッダーバーに表示するグループ名
- `話者: メッセージ` → チャットの発言。話者が「私」なら自分の発言(緑・右)、それ以外は相手の発言(白・左、初出のみ名前表示)
- `話者: [image]` または `話者: [image:見出し:ラベル1=値1,ラベル2=値2]` → 吹き出しなしの「アプリのスクリーンショット」風グラフィックを自前生成(`_render_evidence_chart`)。値が数値なら棒グラフ+「◯回」、日付などのテキストなら右寄せのプレーン表示に自動で切り替わる
- `話者: [sticker]` または `話者: [sticker:困り顔]` → 吹き出しなしのスタンプ風イラストを自前生成(`_render_sticker_face`)。現状は困り顔のみ実装
- (`> テキスト`のナレーションカード構文はパーサーに残っているが、v3以降の台本では未使用)

3本の台本(`scripts/01〜03`)はこの形式で書く。すべてv5(内容強化・1分尺化・画像/スタンプの実グラフィック化・終わり方の強化)まで反映済み。

## 実装・確認したこと

- `background_gen.py`から`compose_frame`/`iter_frames`を切り出し、`line_chat.py`が同じボール物理演算のフレームをそのまま再利用できるようにした
- 全メッセージを毎フレーム再描画していたレンダリング遅延を、吹き出し画像のキャッシュ化で解消(初回テストは2分でタイムアウト → 修正後1381フレームを2分7秒で完了)
- 各バージョンを実際にレンダリングし、複数時点のフレームを目視確認してから次の修正に進んでいる(推測での修正はしていない)

## 使い方

```bash
python3 -m moyasuka.line_chat \
  --script moyasuka/scripts/01-sample.md \
  --seed 4 \
  --audio /tmp/narration.wav \
  --out moyasuka-01.mp4
```

`--audio`省略時は無音のプレースホルダーで尺を概算(VOICEVOX未セットアップでもパイプラインの動作確認ができる)。

## v4: 終わり方をスカッと感のある展開に

オーナー:「すっきりしない終わり方だな」

01の終わり方が、義母が沈黙したまま私が丁寧な一言で締める曖昧な終わり方になっていた。3本とも、以下の型に統一:

1. 対立相手に明確な非を認めさせる一言を入れる(「ごめんなさい、言い過ぎたわ」等)
2. 最後に軽いオチ(ユーモアのある締めの一言・スタンプ)を加える

01は私の「じゃあ記録アプリ、続けますね」という切り返し+義母の[困り顔スタンプ]、02は夫の「丸くなったな、あの人」、03は先輩の「○○さん強すぎ」で締める。02・03も同じタイミングでこの書き方に統一済み。

## v5: 画像・スタンプを実際のグラフィックに、終わり方をさらに強く

オーナー:「画像とかスタンプとかが文字表記になっているので変えて。この動画も今後の動画もかなりスカッとさせる終わり方にして。まだ全然スカッとしないから」

2点対応:

1. **画像・スタンプの実グラフィック化**: `私: [家事記録アプリの画面を送信]`のような角括弧テキストを廃止し、`私: [image:家事記録アプリ:掃除=613,洗濯=890,料理=1200]`のような専用記法に変更。実際に「アプリのスクリーンショット」風の棒グラフ(`_render_evidence_chart`)や「困り顔スタンプ」風のイラスト(`_render_sticker_face`)をPILで自前生成して吹き出しなしで表示する。数値データは棒グラフ、日付などのテキストデータはそのままラベル表示(`私の送信=7/14`のような値は棒グラフにならず右寄せテキストになる)
2. **終わり方をさらに強く**: v4の「謝らせて軽いオチ」では弱かったため、以下の型に変更
   - 対立相手を告発する側を複数人に増やす(01は叔母+義姉、02はママ友の友人が「マウントきつかった」と全員の本音を代弁、03は先輩が「見事な返り討ち」と評する)
   - 主人公は相手を許したり慰めたりしない。「別に責めてません、ただ事実を共有しただけです」のように、冷静・淡々とした態度を貫く(下手に優しくすると相手への同情が生まれ、スカッと感が薄れるため)
   - 対立相手は最後、スタンプ一枚(困り顔)で完全に沈黙し、その様子を周囲が突き放すコメントで締める

## v6: スカッとする瞬間に効果音

オーナー:「最後スカッとするタイミングでこうかんおんを付けて、スクラッチみたいなウェイ系の音」

`moyasuka/sfx.py`を新設。レコードスクラッチ(ピンクノイズ+高速ビブラート)→ハイプ感のあるホーン音(3倍音の加算合成)という2段構えの効果音を、外部素材を一切使わずffmpegのlavfiだけで自前合成した。

台本側には`!sfx:名前`という行(表示は何もしない、時間も進めない0秒のキュー)を追加できるようにし、3本とも対立相手が最後にスタンプを送る直前に配置。スタンプが出る瞬間と効果音が完全に同じタイミングで鳴るようにしている。

音声ミックスは`adelay`(効果音をキュー時刻までずらす)+`amix`(ナレーション/無音トラックと合成)。`normalize=0`にして、無音のプレースホルダートラックと混ぜても効果音の音量が不必要に下がらないようにした。

## v7: 効果音を「デデデデデーン」に差し替え、BGMを追加

オーナー(v6の音を聞いたうえで):「ホーンはだめだよ　でででででデェェェェン　みたいなの音がいいのに。後小さい音でいいからBGMは付けて」

2点対応:

1. **効果音の作り直し**: ハイプホーンをやめ、低音の短い連打(5回、`aevalsrc`で低いサイン波+倍音を減衰エンベロープで叩く)が徐々に音量を上げながら続き、最後に長く尾を引く1発(減衰を遅くして「デェェェェン」の余韻を出す)で締める構成に変更。スクラッチ部分はv6のまま流用(そちらへの指摘はなかったため)。関数名・効果音キー名も`scratch_hype`→`scratch_dun`に変更
2. **BGMの追加**: `moyasuka/bgm.py`を新設。ペンタトニックの短いフレーズ(C-E-G-E-A-G-E-D)を1音ずつ減衰エンベロープ付きのプラック音(ピッキング音)としてnumpyで合成し、動画の尺に合わせてループ。デフォルト音量は控えめ(振幅0.16)で、常時BGMとして重ねる(スタンプ演出のsfxとは別トラックとして常に流れる)。実レンダリング後、`volumedetect`でBGM区間(平均-24.9dB、控えめ)と効果音区間(ピーク-0.0dB、しっかり大きい)を確認し、狙い通りの音量バランスになっていることを検証

## v8: メッセージごとの通知音を追加

オーナー:「全然参考にしてないよね？同じような音を使用してよ」

参考動画の実際の音声を直接取得・模倣しようと`yt-dlp`でダウンロードを試みたが、このサンドボックスのネットワークポリシーがYouTubeの動画/音声CDNをブロックしており(WebFetchで`youtube.com`が403になるのと同じ制約)、実際の音声を取得する手段がないことを確認した。

代わりに、抜け落ちていた本質的な部分を直した: このジャンルの動画は、クライマックスの効果音だけでなく、**メッセージが1通届くたびに通知音が鳴る**のが実際の音の主成分だった。これまでは効果音(`!sfx:`キュー1回のみ)とBGMしか実装しておらず、一番基本的な「メッセージ音」が丸ごと抜けていた。

`sfx.py`に`generate_message_pop`を追加(2音の短い上昇チャイム、既存の減衰エンベロープ方式で自前合成)。台本側の指定は不要で、すべてのメッセージ吹き出しの到着タイミングに自動で鳴るようにした(`line_chat.py`の`render_video`で`visual_arrivals`から自動生成)。同じ音を毎回合成し直さず、名前ごとにキャッシュしてから使い回す形に`_mix_audio`を修正(30回前後鳴るため)。

実レンダリング後、`volumedetect`でメッセージ到着タイミングの音量ピークが、何も鳴っていない区間より明確に高いことを確認した。

## v9: クライマックス効果音を効果音ラボの実素材に差し替え

オーナー:「効果音ラボの男衆イヤホォーがいい」

自前合成の「デデデデデーン」をやめ、効果音ラボ(soundeffect-lab.info)の「男衆「イヤッホー！」」に差し替えた。このサイトもこのサンドボックスからは接続不可(YouTube本体と同じ理由、`curl`で403を確認済み)だったため、オーナーが手元でダウンロードしてチャットに添付、それを受け取って`moyasuka/assets/sfx/otoko_iyahho.mp3`として組み込んだ。

- これは唯一「完全自前生成」の方針から外れる素材。ライセンス条件(商用利用無料・クレジット表記不要、素材単体の再配布は禁止)を`moyasuka/assets/sfx/NOTICE.md`に明記
- `sfx.py`の`use_otoko_iyahho`がmp3→wav変換して既存の合成音と同じミックス経路に載せる。台本側の`!sfx:`キュー名を`scratch_dun`→`otoko_iyahho`に変更
- メッセージ到着音(`message_pop`)は引き続き自前合成のまま維持(クライマックス以外は変更対象外という理解で進めた)
- 実レンダリング後、クライマックス区間の音量ピーク(-0.9dB)を確認
