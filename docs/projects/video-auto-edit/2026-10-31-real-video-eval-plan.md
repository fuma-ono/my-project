### 2.2 台本のファイル(任意。文字誤り率を測るため)
台本どおりに読んだ動画は、同じ名前の `.txt`(例: `V1.mp4` に対して `V1.txt`)を一緒に置くと、文字起こしの誤り率を自動計算する。台本から外れた箇所があれば教えてほしい(外れた分は誤りとして数えられてしまうため)。

### 2.3 台本案

**台本1(通常・約40秒)**
> こんにちは。今日は、毎朝の習慣について話したいと思います。私は朝起きたら、まずコップ一杯の水を飲みます。そのあと、十分くらい散歩をして、頭をすっきりさせてから仕事を始めます。最初は続かなかったんですが、三か月くらいたって、ようやく慣れてきました。みなさんも、無理のない範囲で試してみてください。

**台本2(言い淀み・言い直し。【】は自然に入れる)**
> 【えーと】、今日は、週末に行った旅行の話をします。行き先は、【あのー】、京都です。土曜日の朝、新幹線で、【いや、】じゃなくて、高速バスで出発しました。【えー】、着いてすぐに、お寺を三つ回りました。【まあ】、ちょっと歩きすぎて、夜はすぐ寝てしまいました。

**台本3(長い文・数字・英語)**
> 今回紹介するのは、2026年に発売されたばかりのワイヤレスイヤホンで、ノイズキャンセリングの性能が前のモデルと比べておよそ1.5倍に向上しているうえに、バッテリーも最大で30時間持つので、通勤や出張が多い人にはかなりおすすめできる製品だと思います。iPhoneだけでなくAndroidのスマートフォンでも、専用アプリからイコライザーを細かく調整できるのも便利なポイントです。

## 3. 評価手順(動画が届いたら実施)

```bash
# 依存: faster-whisper, budoux, soundfile, scipy (+ bgm-pipeline の依存 numpy/scipy)
python docs/projects/video-auto-edit/poc/run_eval.py <動画フォルダ> <出力フォルダ> small medium
# 設定値の比較(無音のしきい値・最短無音・前後の余白)
VEDIT_NOISE_DB=-40 VEDIT_MIN_SIL=0.6 VEDIT_PAD=0.15 python .../run_eval.py <動画フォルダ> <出力フォルダ2> small
```

出力:
- `<出力>/<動画名>/out_small.mp4`, `out_medium.mp4`: オーナー確認用。このチャットにファイルとして送る
- `<出力>/<動画名>/review.md`: 自動チェックの結果とオーナー記入欄
- `<出力>/summary.md`: 全動画の処理時間・自動チェック件数

### 3.1 評価項目と測り方

| # | 項目 | 自動で出すもの(候補) | 人が確認すること |
|---|---|---|---|
| 1 | 文字起こしの誤り | 台本があれば文字誤り率 | テロップの誤字 |
| 2 | 語頭・語尾の欠け | 残す区間の境界が単語の途中にある箇所 | 該当箇所を聞く |
| 3 | 言い淀みの検出漏れ | 認識された言い淀みと除去の有無 | Whisper が文字にしなかった言い淀みが残っていないか(**自動では検出できない**) |
| 4 | 必要な発言の誤カット | 高: 言い淀みの除去や短い区間の破棄に巻き込まれた単語 / 低: 無音と判定した区間にかかった単語 | 該当箇所を聞く |
| 5 | テロップの表示タイミング | 表示0.8秒未満、1秒あたり8字超 | 声とずれていないか |
| 6 | 不自然な改行 | 1行の上限字数超え、3行以上 | 文節の途中で切れていないか |
| 7 | BGMと声のバランス | 全体のラウドネス(LUFS)とピーク | 声が聞き取りにくくないか(**人の判断**) |
| 8 | 処理時間 | 工程ごとの実測秒数 | — |
| 9 | 1本あたりの追加費用 | 外部API呼び出しの有無 | — |

### 3.2 動画ごとの総合評価(3段階)

## 5. 評価のために行ったスクリプト修正(すべて `poc/` 内。既存プロジェクトへの影響なし)

| 修正 | 理由 |
|---|---|
| テロップの座標系・文字サイズ・1行の字数を入力動画の解像度に合わせた(回転メタデータも考慮) | 縦動画でテロップが画面からはみ出すことを確認したため(修正前後の画面で確認)。スマホの縦撮りが評価対象になる可能性が高い |
| 単語の時刻・削除理由(無音/言い淀み/短い区間の破棄)を JSON に保存 | 誤カットの候補を自動で抽出するため |
| 無音のしきい値・最短無音・余白を環境変数で変更可能に(既定値は -35dB / 0.5秒 / 0.12秒のまま) | 設定値の比較のため |
| 作業フォルダを絶対パス化 | 相対パスを渡すと BGM の生成先がずれて失敗したため |

| ID | 問題 | 再現条件 | 原因の仮説 | 改善案 |
|---|---|---|---|---|

| P6 | Whisper は言い淀みを文字にしないことがある | 一般的に知られている性質。実動画では未確認 | 学習データが言い淀みを省いた字幕であるため | 実動画で発生頻度を測る。多ければ音響的な検出(短い有声区間など)を検討 |

## 7. 推奨モデルと設定値(暫定)

実動画で未検証のため**暫定**。実動画の評価後に確定する。
- モデル: **small**(合成音声では誤りが少なく、medium の約2.4倍の速さで文字起こしできる)。実動画で small の文字誤り率が明らかに高い場合は medium
- 無音: -35dB / 0.5秒以上、余白 0.12秒(第1回の値)。雑音のある V3 では、しきい値を上げる(-30dB など)比較が必要になる見込み
