# BGM長尺動画の伸び悩みと高評価/コメント ゼロについて(2026-08-17)

## 観測事実(W32〜W34、YouTube Data API実測)

- 長尺6本の再生数は5〜18回のレンジで、公開から数日〜1週間以上経っても大きく伸びていない
- Shorts2本(194回・269回)は同期間の長尺の15〜20倍の再生数
- 高評価・コメントは**長尺・Shorts問わず全動画でゼロ**(2026-08-17時点)

## 原因仮説

1. **発見経路がほぼShorts経由のみ**: チャンネル登録者・外部流入がまだ薄く、長尺動画は検索/おすすめに乗るための初速(視聴維持率・CTR等)を稼げていない可能性が高い。Shortsのフィード配信の方が新規チャンネルでも露出しやすい構造的な差
2. **エンゲージメント導線が弱い**: 動画内・概要欄に「高評価/コメントをお願いします」の明示的な呼びかけがない(現在のdescription_templateには含まれていない)
3. **YouTube Analyticsのスコープ未取得(タスク#24)**: インプレッション数・CTR・視聴維持率が見えないため、「見られているが最後まで見られていない」のか「そもそも表示されていない」のか切り分けができていない — 原因診断の精度が低い状態が続いている

## 打ち手(提案、未実施)

- **概要欄に軽い呼びかけを追加**: 「作業のお供に高評価いただけると嬉しいです」程度の一文をdescription_templateに追加(強引な誘導文言は避ける)
- **Shorts→長尺の導線をさらに強化**: 既に一部実施済み(Shortsの概要欄から直近長尺動画へリンク)。固定コメントでも同じ導線を追加する案
- **タスク#24(YouTube Analyticsスコープ取得)を優先度を上げて着手**: 現状の「views/likes/commentsのみ」では打ち手の効果検証ができない。次回スコープ追加のOAuth再認可のタイミングで合わせて取得したい

## 次のアクション

上記「打ち手」はまだコード・description_templateへの反映を行っていない(観測と仮説の記録のみ)。オーナー確認の上、着手するかどうかを判断する。

## 2026-08-25追記: オーナー指示を受けて実行

オーナー指示「それで進めてくれ。どうしたら再生数が伸びるのかをしっかり考えて行動して」を受け、着手可能な打ち手を実行した。

- **概要欄の呼びかけ追加(実施済み)**: `build_description()`/`_shorts_description()`を全面日本語に書き直し、カテゴリ別(sleep/focus)のコメント誘発質問文(`ENGAGEMENT_QUESTION`)を追加。**公開済み15本すべてに`videos.update`で遡って反映済み**(過去に「日本語のhook/aboutの後に英語の定型文が続く」という一貫性の欠如があったことも同時に発見・修正)
- **Shorts頻度を週3回→毎日に変更(実施済み)**: このチャンネル自身の実測データ(Shorts平均194〜269回 vs 長尺5〜18回、15〜20倍)に基づく判断。限界コストが¥0のため、実測で勝っているチャンネル(Shorts)へ配分を増やすのが最も確度の高い一手と判断した。月1回、頻度を上げたことで視聴者が飽きていないか(再生数の頭打ち)を確認する運用を合わせて追加
- **YouTube Analyticsスコープ取得(タスク#24、未着手のまま)**: `youtube_analytics.py`のdocstring記載の通り、device-flow OAuthでは`yt-analytics.readonly`が構造的に取得不可と判明済み。オーナー自身のPCでの認可コードフロー(note_publish/と同じ制約)が必要で、コード自体もまだ実装されていない。CTR・視聴維持率が見えない限り「露出不足」か「離脱」かの切り分けができない状態は変わっておらず、これが最大の未解決課題として残っている

## 2026-08-27追記: ピアノプリセット導入後の完全自動化方針

オーナー指示「あとは自動で判断して、動画制作を進めていってほしい。また、アップロードの頻度も自動化して。つまり完全自動化で」を受け、コンテンツ制作の意思決定も含めて自律運用に切り替える。

**前提として、公開頻度自体は既に完全自動**: Shorts(毎日、`trig_01AeLUHacXf7rCAmY31gNPy9`)・長尺(週1、`trig_018Nb6cxD93emms1eGH3XdTj`)ともcronで無人実行しており、オーナー確認は元々不要。今回追加するのは「次に何を作るか」の判断部分。

piano_hisaishi_style(2026-08-27公開、`kGPrXC9uaQM`)導入時にオーナーと合意したロードマップ(STEP7〜9)を、以降は**確認を挟まず自動実行する**判断基準として明文化する:

- **判断のタイミング**: 週次経営レビュー(`trig_013yxMgWCzC44RsjBd9mGNCn`)のたびに、直近2週間以上ライブになっている動画の再生数(views/likes/comments、YouTube Analyticsスコープが無いため現状はこの3指標のみ)を確認する
- **新プリセット・新バリエーションを追加する判断基準**:
  - あるプリセット(特にpiano系)の直近実績が、同時期の他プリセット平均を明確に上回っている(目安: 2倍以上) → その系統のバリエーションを増やす(例: piano_hisaishi_styleが好調なら「雨」「夜」「カフェ」など別の雰囲気のピアノプリセットを追加)
  - 全体的に横ばい・低迷 → 新規追加より先に、導線(概要欄・サムネイル・タイトル)の見直しを優先する
- **3時間版を追加する判断基準**: 該当プリセットの1時間版が2週間以上ライブで、再生数が他プリセットの平均以上 → 3時間版を追加する
- **新プリセット追加時の実装方針**: `piano_hisaishi_style`のように、音源(`presets.py`)→サムネイル→動画→YouTube公開までを一気通貫で実行してよい。ただしサムネイルに実写を使う場合、オーナー提供の写真が無ければ抽象デザイン(`thumbnail.make_thumbnail`)で暫定運用し、次にオーナーから写真が届いたタイミングで差し替える(写真を待って新プリセットの公開自体を止めない)
- **オーナーへの確認が必要なケース(例外)**: 音質・音楽ジャンルそのものを大きく変える場合(ピアノ以外の新楽器ジャンルなど)、既存プリセットの見た目/音を破壊的に変更する場合、YouTube規約・収益化に関わる判断。それ以外(既存路線の延長線上のバリエーション追加、頻度調整)は判断して即実行し、週次経営レビューやダッシュボードのログで事後報告する
