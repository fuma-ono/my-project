# note売上化のための成長戦略(社長決定, 2026-08-01)

オーナーより「noteも音楽に固執するな、SNSで告知して読者を増やせ、結果を出せ、アジャイルかウォーターフォールで進めろ、AIで自動化して会社を大きくしろ」との指示。以下、決定と実行計画。

## 進め方の決定: アジャイル(ウォーターフォールは不採用)

理由: コンテンツマーケティングは「何が読まれるか」を事前に確定できない。ウォーターフォール(要件→設計→実装→検証を1回で通す)は、閲覧数・スキ数という実測フィードバックを次の意思決定に反映できず、外れたときのやり直しコストが大きい。**1週間スプリントの計画→公開→計測→振り返りを回すアジャイル**を採用する。

### 週次スプリントの型

1. **計画**: 今週公開する記事1本(既存Routineが自動下書き)+ SNS告知1〜2本を決める
2. **公開**: note記事(オーナーが投稿)+ SNS告知(オーナーがコピペ投稿)
3. **計測**: 次週レビュー時にスキ数・閲覧数(オーナー申告 or note公式ダッシュボードのスクショ)を確認
4. **振り返り**: 伸びた記事の型(タイトル・切り口)を次週のネタ選定に反映。`docs/ORG.md`のマーケティング部の役割として明文化。

## 決定1: コンテンツの2本柱化(音楽/睡眠に固執しない)

これまでの note 記事はすべて「睡眠・集中サウンド」という1テーマに閉じていた。BGM動画・アプリとのシナジーは残しつつ、**読者層を広げるための第2の柱**を追加する。

- **柱A(既存): 睡眠・集中サウンドのゆる記事** — BGM動画・アプリへの導線
- **柱B(新設): 個人開発・お金・AI経営の記事** — 「AIに会社を経営させてみたら4事業になった話」「経費管理アプリが無くて自分で作った話」等。2026年はAIエージェントが自律的に意思決定・実行するテーマ自体が注目されており(このプロジェクトそのものが実例)、実体験ベースの一次情報として強い。expense-app・BGM動画・アプリすべてへの導線にもなる「メタ記事」が作れる。

具体的なトピック案は `docs/marketing/2026-08-content-topics.md` に「柱B」として追記する。

## 決定2: SNS(X/旧Twitter)を新規開設し、note告知の主導線にする

- note読者の主要な流入元はX(Twitter)であり、これまでの6アカウント(Google/YouTube/Google Play/Instagram/TikTok/note.com)にXが含まれていなかった欠落を埋める。Instagram/TikTokは動画向けで、テキスト記事の告知導線としては弱い。
- 運用: 新しい note 記事を公開するたびに、**X投稿文(フック+リンク)を1〜2本ドラフト**する。投稿はオーナーがコピペで実施(X APIでの自動投稿は初期は行わない。乗っ取り・凍結リスクを避けるため手動運用から始める)。
- アカウント作成手順は `docs/setup-guide/template.html` に追記済み(コピペ用ガイド、既存の6アカウントと同じ形式)。

## 決定3: 自動化の拡張

既存の週次note下書きRoutine(毎週月曜)を拡張し、**note下書きに加えてX投稿文のドラフトも同時に作成**するようにする。ドラフトは「SNS投稿キュー」ページ(note投稿キューと同じコピペ形式)にまとめ、オーナーは週1回まとめてコピペするだけで済む運用にする。

## 測定指標(次回レビューで確認する)

- note: 記事ごとのスキ数・閲覧数・フォロワー数の推移
- X: フォロワー数、note記事リンクのクリック数(目安でよい)
- 上記が実装済みの数値目標(README記載): スキ数が二桁に乗る・フォロワーが増え始める段階で有料マガジンへ移行

## オーナーへの依頼

- X(Twitter)アカウントの作成(`docs/setup-guide/template.html` の手順参照)
- 週次でのnote記事投稿・X投稿(コピペのみ、文面はこちらで用意)
- 可能であれば次回レビュー時にnote公式ダッシュボードの閲覧数・スキ数を共有(振り返りの精度が上がる)
