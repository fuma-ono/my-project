# Threads投稿戦略の再設計:「商品を売る投稿」から「ネタの中に商品が登場する投稿」へ

2026-09-13、オーナー指示。

## 背景・問題意識

これまでの投稿構成は「悩み→気づき→商品→利用シーン→CTA」の固定パターンで、商品紹介としては成立していたが、Threads上で拡散されるSNSコンテンツとしては弱い。商品ありきで構成を埋める設計になっていたため、フックが弱く、毎回似た構造・似たCTAになりがちだった。

## 実装前の監査結果

以下5点を確認した結果、**コード変更はほぼ不要**であることが分かった。

1. **投稿生成処理**: 専用スクリプトは存在しない。CCR Routine「Threadsアフィリエイト 毎日投稿案生成」が発火するたびに、Claudeが`post-template.md`の指示に従って`pending/*.json`を直接書く運用。→ 変更対象は`post-template.md`の文面そのもの。
2. **投稿テンプレート**: 旧構成・旧4パターンがここで定義されていた。→ 全面改訂(本コミットで実施)。
3. **`publish-log.jsonl`**: `post_type`は自由文字列としてそのまま記録されるだけで、4値のバリデーションは存在しない(`publish.py`の`log_result()`)。→ **無改修**で新タイプ値に対応可能。
4. **`analyze.py`**: `group_by(entries, "post_type")`は値の種類を決め打ちしない汎用実装。`MIN_SAMPLE_FOR_JUDGEMENT=10`も既に「サンプル不足は判断不能」を実装済み。→ 判定ロジックは無改修。ただし`reposts`/`quotes`/`shares`が集計はされているのに表示されていなかったため、表示列として追加した(データ追加ではなく、既存データの可視化のみ)。
5. **自動返信処理**(`fetch_replies.py`/`send_replies.py`/ガードライン文書): 投稿本文を`original_post_text`として丸ごと文脈情報に使うだけで、構造やpost_typeに依存していない。→ **無改修**。

## 変更内容

### 1. `post-template.md`(全面改訂)

- 基本思想を「商品→投稿」から「商品の特徴・悩み→SNSで興味を持たれるネタ→投稿→商品→自然なCTA」の順に転換
- 投稿パターンを旧4種(empathy/discovery/comparison/summary)から新9種に変更:
  `unknown_fact`(知らなかった事実)/ `relatable`(あるある・共感)/ `problem_solution`(問題提起→解決)/ `comparison`(比較)/ `ranking`(ランキング・厳選)/ `failure`(失敗・後悔)/ `discovery`(もっと早く知りたかった)/ `debate`(議論・質問)/ `use_case`(意外な使い方)
- 単純ローテーションを廃止し、商品との相性で都度選ぶ方式に変更
- 「フック生成・自己評価」節を新設: 【PR】直後の1〜2文について、続きが気になるか/自分ごと化できるか/意外性があるか/疑問が生まれるか/共感できるか、の5基準で自己評価し、単なる商品紹介文なら書き直す運用を明文化
- 禁止・抑制事項を追加: スペック羅列、メーカー説明の言い換えのみ、冒頭からの商品名の強い押し出し、「おすすめです/便利です」だけで終わる投稿、毎回同じ構成・同じCTA、過剰な広告表現、根拠のない数値効果の断定、バズ狙いの誇張・虚偽表現
- PR表記必須・冒頭配置・500文字制限・11項目の商品選定基準・絵文字ルール・リンク必須ルール等、既存の厳守事項は**変更なし**で維持

### 2. `analyze.py`(表示追加のみ)

`format_group_table()`の表に`replies`/`reposts`/`quotes`/`shares`列を追加した。判定ロジック(`MIN_SAMPLE_FOR_JUDGEMENT`によるサンプル不足時の「判断不能」表示)は変更していない。

### 3. CCR Routine「Threadsアフィリエイト 毎日投稿案生成」の指示文

旧4パターンのローテーション指示・旧構成(悩み→気づき→商品→利用シーン→CTA)の明示を削除し、`post-template.md`の新方針(9パターン・フック生成・禁止事項)を参照する形に更新した。

### 変更しなかったもの

- `publish.py`(PR表記検証・アフィリエイトリンク検証・投稿API呼び出し・`automation_guard`連携)
- `fetch_replies.py` / `send_replies.py` / `docs/marketing/2026-09-10-threads-auto-reply-guardrails.md`
- `automation_guard.py` / `decision_log.py` / `research.py`
- `analyze.py`の判定ロジック・しきい値(`MIN_SAMPLE_FOR_JUDGEMENT=10`)
- 商品選定の11項目基準・30日重複回避・リンク必須ルール

## 分析の運用

30〜50投稿まで待たず、**10投稿たまるごとに`analyze.py`でpost_type別の集計を確認する**。ただし1タイプあたりのサンプルが10件未満なら既存ロジックが自動的に「判断不能」と明示するため、少数データから勝ちパターンを断定しない(この閾値・挙動は変更していない)。

評価は以下を分けて見る(表示数が多い=勝ちとは判断しない、最終的にはアフィリエイト報酬・利益を最重視する):

- 拡散: views / reposts / quotes / shares
- エンゲージメント: likes / replies
- アフィリエイト: clicks(合算値である点に注意)/ 成約・報酬(手動突合)

プロフィール遷移数・フォロワー数(「集客」に相当)は、Threads Insights APIの投稿単位メトリクスには存在しないことを2026-09-09時点で確認済みのため、今回も対応していない(API制約であり、実装漏れではない)。

## 今回は実装しないもの

AIによる完全自律的な戦略変更(投稿タイプの自動選択最適化・自動でのパラメータ調整等)はまだ実装しない。現段階は「よりバズりやすい投稿構造を複数用意し、検証データを集める」段階であり、`docs/marketing/2026-09-10-ai-autonomous-operation-design.md`のPhase 2(投稿30件超後の戦略変更ロジック)の位置づけは変わらない。
