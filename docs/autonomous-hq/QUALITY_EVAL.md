# QUALITY_EVAL — AI 編集者の品質評価環境

最終更新: 2026-11-22(UTC)。目的: 動画を**書き出せる**ことではなく、プロの編集者のように、素材の内容・目的を理解して**魅力的な完成動画を作れる**AI に育てるための、**測る仕組み**。
最優先事項は「AI 編集品質の向上」(Owner 指示、2026-11-22)。無料・OSS・ローカル処理のみ。外部 API・有料サービス・API キーは使わない。

## 1. 評価の対象と範囲
| エンジン | 内容 | この評価の対象 |
|---|---|---|
| **ハイライト編集エンジン**(`vae/highlight/`) | 複数の動画から、見どころを選び、並べ、BGM・字幕をつけて1本にする。Owner の構想の中心 | **対象** |
| 製品の単一動画パイプライン(`vae/pipeline.py`) | 1 本の動画の言い淀み・無音のカット、字幕、BGM | **対象外**(既存の QUALITY_GATES で技術面を確認済み。編集品質は、字幕・音声の軸だけ、後で同じ基準で測る提案) |
| Sonnet 版の構成判断(`planner_llm.py`) | 有料 API。**今は使わない**(API キー未登録・保留) | 対象外 |

## 2. 原則
1. **書き出しの成功は品質ではない。** 全フレームが復号でき、音声と長さが合い、True Peak が上限内、は『前提(gate)』として別に出す。
2. **合成素材は『動作確認』、実動画は『品質評価』。** 合成で良い結果が出ても、編集品質の証拠にしない。レポートの区分に必ず出す。
3. **エンジン自身の採点で、エンジンを採点しない。** 評価は、出力動画と元素材の物理的な測定値(明るさ・鮮明さ・動き・音量・時刻・文の区切り)から、独立した物差しで測る(`vae/quality.py`)。
4. **測れないものは、測ったふりをしない。** 好み・聴感・音楽の相性・満足度は『自動では測れない』とし、人の評価(1〜5)の欄を用意する。私(AI)の目視は『AI の観察』と明記し、人の評価の代わりにしない。
5. **数値だけでなく、完成動画と具体的な問題点で示す。** レポートには、採用区間(時刻)、証拠の画像、自動で検出した問題点(時刻つき)を出す。
6. **再実行できる。** 同じ素材(サイズ・ハッシュを記録)・同じ設定・同じコミットで、同じ結果になる。解析の再現性は `--no-cache` の 2 回実行で確かめる。

## 3. 評価軸(9 つ)と、自動指標・人の評価
点数: 自動指標は 0〜5(規則は下の表)。軸のスコア = 自動指標の平均。人の評価は 1〜5(5 = プロの編集者が作ったと言われても違和感がない / 4 = 公開できる(気になる点 1〜2)/ 3 = 使えるが素人っぽい / 2 = 明らかな欠点が複数 / 1 = 使えない)。
**閾値は暫定。** Owner の承認で確定する(大きく変える場合は、Owner に提案する)。

| 軸 | 自動指標(0〜5 点の規則) | 人の目・耳が必要な点 |
|---|---|---|
| **映像・内容の理解** | 使える動画・使えない動画の見分けの一致率(正解ラベル `eval/labels/` との比較。100% で 5、50% 以下で 0) | 内容を正しく理解して選んでいるか(場面の種類・人物・出来事) |
| **ベストシーンの選択** | 使えない映像(黒・白飛び・ぼけ・大きなブレ)の混入率(0% で 5、20% 以上で 0)/ 選んだ場面の質の順位(素材全体の中での平均パーセンタイル。75 以上で 5、50 以下で 0。物差しは、明るさ・鮮明さ・安定・顔から作った、エンジンとは別の重み) | 本当に見どころか(感情・動き・決定的瞬間) |
| **ストーリー構成** | 同じ映像の繰り返し(出力内の離れた時刻の同じ画。0 秒で 5、4 秒以上で 0)/ 同じ動画の同じ時間帯の重複 / 使えない動画の採用数 / 使える動画の採用率 / 目標の長さとの差 / 撮影順どおりか(撮影日時が使えるときだけ) | 流れが自然で、見たくなる構成か。起承転結・導入と締め |
| **カット・テンポ** | 1 区間の長さの中央値(2.5〜6 秒で 5)/ 2 秒未満の割合 / 元動画の切り替わりをまたぐ区間(0 個で 5)/ **文の途中で切れている数**(ASR の文の区切りで測る。エンジンの VAD とは別)/ カットの位置の、拍からのずれ | カットの切れ目・テンポが気持ちよいか |
| **演出・トランジション** | 演出の機能の実装率(`EFFECT_CAPABILITIES` の 14 項目のうち実装済み ÷ 14 × 5) | 演出・つなぎが映像を引き立てているか |
| **音楽・音声との調和** | True Peak(-1 dBTP 以下で 5)/ 統合音量と -16 LUFS の差 / ラウドネスレンジ(7 LU 以下で 5)/ 会話の区間とそれ以外の音量差(6 LU 以上で 5) | **BGM の相性・声の聞き取りやすさ(聴感)** |
| **字幕・テロップ** | 規則違反(0.8 秒未満・重なり)/ 会話の秒数のうち字幕で覆えた割合 / 読む速さ(8 字/秒以下で 5)/ 文字誤り率(台本があるときだけ。合成素材のみ) | 字幕の内容の正しさ・見た目・タイミング(実動画は正しい台本が無いため**未測定**) |
| **映像の仕上がり** | 黒フレーム・静止の合計秒 / 暗すぎる時間の割合 / カットでの明るさの段差 / 出力の短辺の画素数 | 色・明るさ・画面の見栄え |
| **完成動画としての総合品質** | **自動では決めない**(自動指標の平均は参考値として別に出す) | 見て驚き・満足を感じるか。プロの編集者が作ったと言えるか |

## 4. 素材(`eval/sets.json`。動画ファイルは Git に入れない)
| セット | 区分 | 内容 | 使い方 |
|---|---|---|---|
| **SYN-1** | 合成(動作確認) | 6 本を生成: 台本つきの音声の動画、場面、真っ黒、同じ場面の撮り直し、途中に切り替わりがある動画、縦動画 | 期待される振る舞いをアサーションで確かめる。**編集品質の評価ではない** |
| **REAL-1** | 実動画 | clip01(結婚式の受付、4K、35.5 秒、会話あり) | 1 本の中の場面選択・カット・字幕 |
| **REAL-2** | 実動画の**代用** | REAL-1 を元の切り替わりで 3 場面に分けたもの | 複数動画の扱いの参考。同じ撮影から分けたため、本物の複数素材の代わりにならない |
| **REAL-3** | 実動画 | clip01 + Owner のアップロード 3 本(IMG_4215・IMG_4216・IMG_4217) | 質の混ざった複数素材(良好 1 + 使えない 3)。不要素材の除外・縦横の混在 |
**権利上の制約**: すべて Owner の撮影素材。clip01 は第三者(列席者)の顔・声が写る。**ローカル評価のみ。外部サービス・API への送信禁止、Git・公開・再配布禁止。** 利用許諾が確認できていない素材(Coverr・Vimeo・ISO Republic など)は、ダウンロードも評価にも使わない。
**素材の限界**: 良好な実動画は clip01 の 1 本だけ。**ベストシーンの選択・ストーリー構成・BGM との相性を本格的に評価するには、良好な実動画が複数本要る**(後述の次の作業)。

## 5. 再現できる評価手順
```bash
cd personal-side-projects/video-auto-edit && . /tmp/vedit-poc/.venv/bin/activate   # または make setup
python tools/quality_eval.py run SYN-1  OUT/syn     # 合成: 動作確認(自動で素材を生成)
python tools/quality_eval.py run REAL-3 OUT/real3   # 実動画: 品質評価
python tools/quality_eval.py sheet OUT/real3        # 人の評価シートを作る(完成動画 highlight.mp4 を見て・聞いて記入)
python tools/quality_eval.py compare OUT/before OUT/after   # 改善後の再評価(差分と回帰)
python tools/quality_eval.py run REAL-3 OUT/again --no-cache  # 解析も含めた再現性の確認(EDL・出力の画が同一か)
```
出力: `highlight.mp4`(完成動画)、`results.json`(全指標)、`report.md`(軸ごとのスコア・指標の内訳・採用区間・自動で検出した問題点・再現性)、`evidence/`(各区間・カット前後・字幕の画像)。
設定は固定: 文字起こし medium(温度 0・VAD・条件付けなし)、字幕 clean、BGM は自動生成(seed 1)、雰囲気・長さは自動。コミット・素材のサイズとハッシュ・ライブラリの版を `results.json` に記録する。
テスト: `pytest tests/test_quality.py`(測定器の動作確認。モデル不要、CI で動く)。

## 6. 結果の読み方・合否
- **回帰の基準**: 改善の前後で `compare` を出し、**どの軸も 0.2 点を超えて悪化しない**こと。悪化したら、理由を説明できるときだけ進める。
- **人の評価の入れ方**: `rating_sheet.md` に記入し、軸ごとの人の評価と、自動スコアを並べて見る。自動スコアが高く、人の評価が低い軸は、**測定器が間違っている**。測定器を直す(基準を変える場合は、Owner に提案する)。

## 7. 既知の限界(測定器の)
- 『使えない映像』『瞬間の質』の物差しは、明るさ・鮮明さ・動き・顔の単純な指標。内容の良し悪しや感情は測れない。
- ベースの特徴量(明るさ・鮮明さ・動き・顔の数)は、エンジンの解析結果と同じ値を使う(独立なのは、組み合わせの重みと閾値)。完全な独立ではない。
- 文の区切りは Whisper(medium)の出力。認識を間違えると、測定も間違う。
- 演出の軸は『機能の有無』の評価で、使われ方の良し悪しは測れない。
