## 1. 確認したことと、その根拠
| 項目 | 結果 | 根拠 |
|---|---|---|
| キーを置ける場所 | **環境変数だけ**。Anthropic のホストには「ネットワークのシークレット」(通信のときに差し込む方式)を使えない。チャットや入力フォームでも預かれない | セッションのドキュメントと、`request_credential` の拒否(api.anthropic.com は不可) |
| 環境変数の見える範囲 | この環境は「個人用」(`scope: personal`)。その環境を使う**オーナーのセッションと、セッション内のコマンド(私を含む)**から読める。既存の変数は `EXPO_TOKEN`、`SUPABASE_URL` | `get_environment` の結果。ドキュメント: 環境変数は環境に平文で保存される |
| セッション終了後の保持 | **環境に保存されるので、セッションが終わっても残る**。以後の新しいセッションにも渡る。消すのはオーナーが環境の設定で行う | ドキュメント(変数は環境の設定。新しいセッションが拾う) |
| ログ・エラー出力への残り方(SDK) | **残らない(実測)**。ダミーのキーで、SDK 2.12.0 の `repr(client)`・例外の文字列・traceback・`ANTHROPIC_LOG=debug` のログを調べ、キーも先頭20文字も出なかった | `scratchpad/keytest/leak.py` を実行(401 を返す手元のサーバーに対して) |
| 残りうる経路 | ① コマンドでキーを表示する(`echo $ANTHROPIC_API_KEY`、`printenv`、`env`)。出力はセッションの記録に残る ② Git へのコミット ③ 予算の台帳 | ① は**フックで止める**ようにした(下)。② は既存のコミット前フックが `sk-…` の形式を検出する(パターンの一致を確認)。③ 台帳にはキーを書かない(コードを確認。キーは SDK が環境変数から読み、私たちのコードは値を持たない) |
| キーを失効させる方法 | Console の API キーのページ(platform.claude.com/settings/keys)で「Delete API key」。Admin API ではキーの状態を `active` / `inactive` / `archived` に変えられる | 公式サポート記事(漏えいが疑われるときの手順)、Admin API のキー更新のページ |
| 失効が効くまでの時間・取り消せるか | **書かれていない**(ワークスペースのアーカイブは「数秒以内」と書かれているが、キー単体の記述ではない) | 公式ページ |
| 漏えい時の自動対応 | GitHub の**公開**リポジトリでキーが見つかると、GitHub が Anthropic に通知し、Anthropic が自動で無効化してメールを送る。公開リポジトリ以外には書かれていない | 公式サポート記事(API キーの推奨事項) |
| 利用額の制限 | ① 組織・**ワークスペース**に、月額の上限を設定できる(Console の「Spend limits」)。② 自分で決めた上限に達すると、リクエストは HTTP 400 で止まる(ティアの上限は 429)。③ **キー単位の上限は無い**。④ 前払いクレジットの残高が上限として働くか、自動チャージを切れば超えないかは書かれていない(自動チャージは「想定外の高額利用の安全弁にもなる」と書かれている)。⑤ 通知メールは、直接請求の組織のみと読める | 公式のレート制限・ワークスペース・利用額の上限のページ |
| 注意点 | 「Default Workspace」の上限は、一部の利用を数えない・止めないことがある(プレイグラウンドなど)。Default Workspace に上限を置けるかは、2つのページで記述が食い違い、確定できない | 公式のレート制限のページ(原文)とワークスペースのページ(要約) |
| 利用量・費用の確認場所 | Console の Logs、Usage、Billing。ワークスペース別は Usage and Cost Analytics API | 公式サポート記事 |

## 2. 推奨する運用(オーナーの判断で実施)
1. **専用のワークスペースを作る**(例: `vae-eval`)。Default Workspace は使わない。
2. **そのワークスペースに月額の上限を設定する**(予算 500 円 ≒ 3 ドルより少し下の 3 ドル。為替で 500 円を超えないように)。これが唯一の**サーバー側のハードな上限**。私たちの台帳(500 円)は、送る前の見積もりと記録で、Anthropic 側の請求とは別の確認用。
3. **そのワークスペースだけに紐づいたキーを新しく作る**。他の用途のキーは使わない。
4. 実動画が届き、実行する直前に、キーを環境変数 `ANTHROPIC_API_KEY` として登録する。新しいセッションから有効になる。
5. 実行は **1回**(`--llm run`)。終わったら、Console の Usage と台帳の費用(`python -m vae costs` ではなく `~/.cache/vae/llm_ledger.json`)を照合し、**キーを Console で削除し、環境変数も消す**。
6. キーを登録している間は、チャットにキーを貼らない。画面にキーを出す操作は、フックで止める。

## 3. 今回入れた安全策(コード)
- `.claude/hooks/vae_hooks.py`: `echo`/`printf`/`cat` でキー・トークンの変数を出す操作、`printenv`、引数なしの `env`、`/proc/*/environ` の読み取りを止める。値を出さない確認(`test -n "${ANTHROPIC_API_KEY:-}"`)は通す。テスト 94/94。
- **限界**: `python -c` の中での出力、ヒアドキュメント、変数に入れてからの出力は検出できない。キーを登録している間は、私自身がそれらをしない。
- `planner_llm.py`: キーは SDK が環境変数から読む。私たちのコードは値を保持・出力しない。台帳・ログ・評価シートにキーを書かない。
