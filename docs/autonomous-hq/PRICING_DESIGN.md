価格・上限・商品 ID はすべて設定ファイル `personal-side-projects/video-auto-edit/config/plans.json` で変えられるようにする(コードに書かない)。

## 1. 現在のエンジンと処理原価(実装順序 1)

実測値(4 vCPU・メモリ 15GB のこの開発環境、文字起こしは faster-whisper medium、CPU int8)。

|---|---|---|---|---|
| 実動画 31.1秒(IMG_4217) | 36.8秒 | 文字起こし 22.9秒 | 書き出し 240MB、Python 約2.3GB(モデル込み) | 0円 |
| 実動画 39.4秒(IMG_4216) | 37.8秒 | 文字起こし 21.7秒 | 書き出し 421MB | 0円 |
| 実動画 31.9秒(IMG_4215) | 39.0〜97.4秒 | 文字起こし 21.1〜77.5秒(他の処理と CPU を取り合った回は遅い) | 書き出し 241MB | 0円 |
| 合成 3分 1080x1920(文字起こしは偽物) | 106.5秒 | 音声 64.6・書き出し 39.2 | 書き出し 412MB、Python 398MB | 0円 |
| 合成 5分 1080x1920(文字起こしは偽物) | 160.1秒 | 音声 96.3・書き出し 59.6 | 書き出し 414MB、Python 715MB | 0円 |

見積もり(**推定**。実動画の長尺は未計測 = BLOCKERS B-6):
- 文字起こしは実時間の約0.55〜0.7倍。3分の素材で全体 約3.5〜4分、10分の素材で全体 約11〜13分。
- 音声処理のメモリは長さに比例(5分で 715MB → 10分で約1.4GB)。10分までは現状で収まる。
- 4K の書き出しは未計測。計測するまで設定 `allow_4k` は false にする(PRO でも 1080p で書き出す)。
- 外部 API は使っていないので、API 費用は0円。サーバー費用は「CPU 時間 × 単価(設定値)」で計算する。単価は契約先が決まるまで仮の値(`server_cost_jpy_per_cpu_hour`)。

プランごとの最大負荷(推定): PRO の上限(10分 × 月40本)= 1人あたり月 約8時間の CPU 実時間(4 vCPU を占有)。STANDARD(3分 × 15本)= 約1時間。採算の判断は、実際の原価記録(5章)がたまってから行う。

## 2. 用語とデータモデル(実装順序 2)

保存先は SQLite(標準ライブラリ、無料)。`data/vae.db`。WAL モード。利用枠を変える処理は `BEGIN IMMEDIATE` の1トランザクションで行う(同時リクエストでも二重に数えない)。

| 表 | 主な列 | 役割 |
|---|---|---|
| accounts | id, app_account_token(UUID、一意), created | 利用者。Web(DEV)は cookie の端末 ID を1アカウントに対応させる。iOS は StoreKit の appAccountToken にこの UUID を渡し、購入とアカウントを結び付ける |
| subscriptions | original_transaction_id(主キー), account_id, product_id, plan, expires_at, auto_renew, revoked_at, environment, last_transaction_id, source(apple / dev) | 購読の状態。有効 = 失効日時が未来で、取り消されていない |
| apple_events | id(transaction_id または notification_uuid、主キー), kind, received | 同じ取引・通知を2回処理しない |
| projects | id, account_id, created, state, versions | 1つの編集単位。元動画(複数可)と出力の版を持つ |
| project_videos | project_id, idx, seconds, width, height, fps, hash | 元動画。合計秒数をサーバーで検証する |
| usage | id, account_id, project_id, kind(new_edit / reedit), period(YYYY-MM、日本時間), status(reserved / consumed / released), idempotency_key(一意), plan, created, updated, reason | 利用枠の予約・消費・返却 |
| cost_records | id, account_id, project_id, usage_id, run_kind(new_edit / reedit / manual_render), plan, resolution_class(720p / 1080p / 4k), source_seconds, output_seconds, wall_seconds, cpu_seconds, peak_mb, api_cost_jpy, server_cost_jpy, status, created | 原価の記録 |

## 3. 利用枠のルール(実装順序 3)

### 3.1 回数の数え方
- **新規編集**: プロジェクトの最初の AI 編集(文字起こし → カット → 字幕 → BGM → 書き出し)。月(日本時間の暦月)ごとに数える。
- **AI 再編集**: 完成済みのプロジェクトに対して、AI が映像・音声処理をやり直す操作(編集コンセプトやカットの強さを変えて作り直す)。プロジェクトごとに数える。
- **数えないもの**:
  - 相談・指示文の入力・修正案の確認(処理を始めない操作)
  - 字幕の文章・位置・サイズの手動変更。手動変更の書き出しは、字幕を焼き込むために映像を書き出し直すが、AI 処理ではないので数えない
  - 失敗した処理、キャンセルした処理(予約を返却する)
  - 変更が無い再編集(前回と同じ設定)。前回の出力を返し、予約を返却する

### 3.2 予約 → 消費 / 返却
1. 処理を始める前に、1トランザクションで次を行う。
   - 有効なプランを決める
   - 上限を確認する
   - `usage` に reserved の行を入れる
   - 上限に達していれば、行を入れずに `limit_reached` を返す。自動課金はしない
2. 処理が成功したら consumed にする。
3. 失敗・キャンセルなら released にする。
4. サーバーの再起動で reserved のまま残った行は、起動時に released にする(処理は終わっていないので消費しない)。
5. 上限の判定では、reserved と consumed を合わせて数える(同時に2つ始めて上限を超えることを防ぐ)。
6. クライアントは操作ごとに `Idempotency-Key` を送る。同じキーの再送には同じ予約を返す(リトライによる二重消費を防ぐ)。キーが無い要求はサーバーが作る。この場合は二重送信を防げないので、UI は必ずキーを付ける。

### 3.3 プランの上限の確認(すべてサーバー側)
- **元動画の合計時間**: プロジェクトに動画を足すたびに検証する。処理開始時にも再検証する。
- **複数動画**: FREE は1本だけ。
- **AI 再編集**: 「その時点の有効なプランの上限 − そのプロジェクトで消費・予約済みの回数」。アップグレードすれば残りが増える。
- **ダウングレード・解約後**: 契約期間が終わるまでは、そのプランのまま。期間が終わった後は、FREE の上限を超えるプロジェクト(3分の動画など)の再編集はできない(アップグレードを案内)。作った動画の閲覧・ダウンロード・削除はできる。
- **書き出しの解像度**: 短辺の上限で決める(FREE 720、STANDARD・PRO 1080、PRO の 4K は `allow_4k` が true で、素材の短辺が 2160 以上のとき)。拡大はしない。
- **優先処理(PRO)**: 待ち行列で PRO のジョブを先に処理する。実行中のジョブは止めない。

### 3.4 返却・失敗の扱い
| 場合 | 扱い |
|---|---|
| 解析・書き出しの失敗(エラー・検証不合格) | 返却 |
| 利用者のキャンセル(処理開始前・処理中) | 返却 |
| サーバーの再起動で中断 | 起動時に返却 |
| 同じ設定の再編集(変更なし) | 処理せずに前回の出力を返し、返却 |
| 成功 | 消費 |

## 4. AI 再編集の版管理と部分的な再処理
- 元動画は読むだけで、残す。出力は版ごとに `outputs/v1.mp4`、`v2.mp4` … として残し、修正前の完成動画も保持する。保持期間はジョブの期限(既定24時間)に従う。
- 文字起こしの結果(`transcript.json`)は、元動画のハッシュとモデルを鍵にして残す。再編集では文字起こしをやり直さない(処理時間の大半を省く)。
- 編集計画を作り直した後、残す区間と音声の設定が前回と同じなら、音声のミックスを使い回す。
- 字幕は映像に焼き込むため、字幕を変えたときは映像の書き出しが必要(「変更部分だけ」にできない部分として記録する)。

## 5. 原価の記録と集計
- 処理ごとに次を `cost_records` に入れる。
  - 実時間、CPU 時間(自分のプロセスと子プロセスの合計)、最大メモリ
  - 素材と出力の長さ、解像度の区分、プラン、処理の種類
  - API 費用(0円)、サーバー費用(CPU 時間 × 単価)
- `python -m vae costs` で、プラン別・処理の種類別・解像度別に、件数・平均時間・平均原価を集計する。
- 採算の見積もりは「月額 − 平均原価 × 平均利用回数」。手数料率は設定値で、App Store 手数料の率は契約条件により異なるため仮の値。

## 6. 課金(App Store の定期購読)
- iOS アプリは StoreKit 2 で購入する。購入時に `appAccountToken` = アカウントの UUID を渡す。
- 購入・復元のときは、iOS が `Transaction.currentEntitlements` の署名付き取引(JWS)を `POST /api/billing/apple/transactions` に送る。
- サーバーでの JWS の検証:
  - x5c の証明書チェーンが Apple のルート証明書(設定で指定したファイル)につながること
  - ES256 の署名
  - bundleId
  - 環境(Sandbox / Production)
  - 商品 ID が設定にあること
  - appAccountToken が送ってきたアカウントと一致すること
- 二重登録の防止: originalTransactionId が主キー。別のアカウントに結び付いた購読は付け替えずに 409 を返す。同じ取引の再送は何もしない(冪等)。
- App Store Server Notifications V2(`POST /api/billing/apple/notifications`)。notificationUUID で重複を除く。
  - 更新: 失効日時を延ばす
  - 自動更新オフ: 期間終了まで有効のまま
  - 失効: 期間終了で FREE に戻る
  - 返金・取り消し: 直ちに無効
- 解約後も、契約期間の終わりまでは有効。
- **このリポジトリで行わないこと**(人間の承認が必要):
  - Apple Developer Program への登録(年会費)
  - App Store Connect での商品の作成・価格設定
  - 本物の Apple ルート証明書を使った本番環境での検証
  - 通知を受ける URL の公開
- テストは、テスト内で作った証明書チェーンで署名した JWS を使う。
- DEV 用: 環境変数 `VAE_DEV_BILLING=1` のときだけ、`python -m vae dev-grant` で source=dev の購読を作れる(本物の購入が無い環境で STANDARD / PRO の動作を確認するため)。本番では無効。

## 7. 画面
- マイページ: 現在のプラン、契約期間の終わり、自動更新の有無、今月の新規編集の残り、プロジェクトごとの AI 再編集の残り。
- 動画を選んだ時点で長さを確かめ、上限を超えていれば処理の前に案内する。最終判定はサーバー。
- 上限に達したら、アップグレード画面を出す。そこには価格・期間・自動更新の条件・解約方法を、購入ボタンの前に表示する。
- 無料で使える操作(字幕の手動修正、出力の閲覧・ダウンロード)は、有料登録を求めずにできる。
- Web(DEV)では購入ボタンを出さない(「iOS アプリで購入」と表示する)。iOS アプリの画面は Mac(Xcode)が必要なため、この環境では作れない(BLOCKERS)。
