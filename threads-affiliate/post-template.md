# Threads投稿 構成テンプレート

`docs/marketing/2026-08-18-ai-affiliate-feasibility.md` の方針に基づく。週次Routineが投稿を生成する際はこれに従う。

## ジャンル

2026-09-08にジャンル方針を見直した(詳細は `docs/marketing/2026-09-08-genre-pivot.md`)。Focus & Sleep事業との親和性ではなく、以下5基準で選定する:

1. 数値・サイズで比較できる(効果・効能を語らなくていい)
2. 型番が変わりにくく、来年も同じ悩みで検索される
3. 検索需要はあるのに、まともな比較記事が少ない
4. 3,000〜15,000円(迷って調べる程度の価格帯)
5. 薬機法・景品表示法リスクが低い

現在の対象ジャンル: モバイルバッテリー・電気ケトル・折りたたみ傘・電気毛布(`research.py`の`KEYWORDS`と連動)。ガジェット全般(型番の陳腐化が速く比較記事も飽和)・美容/金融(規制リスクが高い)は扱わない。

## 品質方針(2026-09-08改訂)

初回投稿がスペック羅列型の「広告っぽい」投稿になっていたため、オーナーから改善指示を受けた。詳細は `docs/marketing/2026-09-08-threads-post-quality-guidelines.md` を参照。要点は以下。

### 「商品紹介」投稿の基本構成(6ステップ)

商品にリンクを貼る投稿(下記パターンの「商品紹介」)は、必ずこの順で書く。**スペックの羅列から入らない。**

1. 読者が共感できる悩み
2. 「それ分かる」と思えるあるある
3. 意外な商品・解決策
4. 商品のメリット
5. 実際の使用シーン
6. 自然なCTA(「気になる人は↓」等、リンクへの押し付けがましくない誘導)

### スペック→メリットへの変換(必須)

スペックをそのまま並べない。「そのスペックで何が便利になるか」に翻訳する。

| 悪い例(スペックのまま) | 良い例(メリットに変換) |
|---|---|
| 10000mAh | カイロとして使いながら、スマホの充電にも使える |
| 最高55℃・3段階温度調節 | 朝から夜まで使えて、暑くなったら温度を下げられる |

### 「売るために説明する」のではなく「悩みを解決する過程で紹介する」

これを最重要ルールとする。読者に「これ知らなかった」「便利そう」と思わせた結果としてリンクがクリックされる設計にする。

## 使う構成パターン(5種類をローテーション、商品紹介ばかり連続させない)

1. **共感投稿**: 「これ地味に困らない?」(リンク無し。読者との共感形成が目的)
2. **発見投稿**: 「こんなのあるの知ってた?」(商品への軽い言及はあってもよいが、リンクは無しでもよい)
3. **比較投稿**: 「普通の〇〇 vs △△」(比較軸を提示。リンクは任意)
4. **商品紹介**: 6ステップ構成でアフィリエイトリンクを含む。この投稿のみ`affiliate_link`必須
5. **まとめ投稿**: 「〇〇な人におすすめの3つ」等のリスト形式

商品紹介以外(共感・発見・比較・まとめ)にも積極的に取り組み、**「商品を紹介するアカウント」ではなく「便利な商品を教えてくれるアカウント」**として認識される投稿頻度のバランスを意識する。

## 商品選定基準(スコアリングに加えて考慮する)

`research.py`のスコアは需要・満足度・価格帯の一次フィルタに過ぎない。上位候補の中から実際に書く1件を選ぶときは、以下も満たすものを優先する:
- 悩みが明確で、読者が「それ分かる」と共感できる
- メリットが一瞬で伝わる(説明が長くなりすぎない)
- 衝動的に欲しくなりやすい
- 日常生活で使用シーンを想像しやすい
- 複数の訴求ポイントがある(1つの機能だけでなく、掛け合わせで魅力を出せる)

## 厳守ルール

- **本文の冒頭または末尾に必ずPR表記を入れる**(例: 「【PR】」「#PR」「#広告」)。景品表示法のステマ規制対応、省略不可(商品紹介パターンのみ。リンクを含まない投稿には不要)
- **使ったことのない商品について「使ってみた」「効果があった」等の断定的な体験談を書かない**。「気になっている」「レビューを見ると〜という声が多い」など、事実に基づく表現に留める
- 医療・健康効果を断定しない(「絶対に眠れる」等の表現は使わない)
- 1投稿1商品を基本とする(複数商品を並べる「リンク集」的な投稿はしない。まとめ投稿でも代表1商品程度に絞るか、リンク無しで紹介するに留める)
- 文字数は**アフィリエイトリンクを含めて**Threadsの制限(500文字)以内(`publish.py`が投稿時に本文末尾へリンクを追記するため、`text`単体の文字数だけでなくリンクの長さも見込んで生成すること)

## 出力フォーマット(`pending/*.json`)

```json
{
  "text": "本文(商品紹介パターンはPR表記込み)",
  "affiliate_link": "https://... (楽天アフィリエイトリンク。商品紹介パターン以外はnullでもよい)",
  "product_name": "商品名(社内管理用、投稿には含めなくてよい)",
  "pattern": "共感投稿|発見投稿|比較投稿|商品紹介|まとめ投稿"
}
```

## 計測するKPI(将来実装、現状は`publish-log.jsonl`に本文・リンク・投稿IDのみ記録)

「いいね数」だけで判断しない。表示数・いいね数・返信数・プロフィール遷移数・リンククリック数・成約数・売上を記録し、**表示→プロフィール遷移→リンククリック→購入**のどこで離脱しているかを見る。詳細と実装状況は `docs/marketing/2026-09-08-threads-post-quality-guidelines.md` 参照。
