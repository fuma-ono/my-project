# Threads投稿 構成テンプレート

`docs/marketing/2026-09-09-threads-account-repositioning.md`(2026-09-09、オーナー指示)の方針に基づく。週次→毎日Routineが投稿を生成する際はこれに従う。**このファイルは2026-09-09に全面改訂した。旧版(ジャンルを4カテゴリに限定・5パターン制)は`docs/marketing/2026-09-08-genre-pivot.md`に経緯を残すのみで、運用上は本版が優先する。**

## ジャンル(2026-09-09、限定撤廃)

特定ジャンルに絞らない。以下を幅広く対象にする:

- 生活便利グッズ・キッチン用品・家電
- スマホ・PC周辺機器・旅行用品・車用品
- 防災用品・季節商品・美容/身だしなみ用品
- 収納・掃除用品・AI/Webサービス・その他日常の「これ便利」

ただし無差別ではなく、**「誰かの困りごとを解決する便利なもの」を優先する**。

`research.py`は楽天・Amazonの商品検索APIを使うため、物販ジャンルのみ自動調査できる。AI・Webサービス系のネタは自動化の対象外で、別途手動リサーチ・執筆する。

## 投稿構成の基本形

「商品説明」ではなく、**悩み→気づき→商品→利用シーン→CTA**の順を基本にする。

1. 【PR】(**冒頭に配置**。末尾に小さく書くだけの設計は禁止。アフィリエイトリンクを含む投稿は必須)
2. 「これ、毎日地味に困ってる人いない?」(悩み・あるある)
3. 「調べてたらこんなの見つけた」の展開
4. 商品紹介
5. 「こういう場面で便利」(利用シーン)
6. 必要最低限の特徴(スペックそのものではなく、メリットに変換したもの。個数を絞る)
7. 「気になる人は↓」(自然なCTA)+ 商品リンク

リンクを含めると、Threads側が自動でリンク先のOGP画像をカード形式で表示する(実機で確認済み)。**画像を別途アップロードする実装は不要**。

### スペック→メリットへの変換(必須)

スペックをそのまま並べない。「そのスペックで何が便利になるか」に翻訳する。

| 悪い例(スペックのまま) | 良い例(メリットに変換) |
|---|---|
| 10000mAh | カイロとして使いながら、スマホの充電にも使える |
| 最高55℃・3段階温度調節 | 朝から夜まで使えて、暑くなったら温度を下げられる |

### 「売るために説明する」のではなく「悩みを解決する過程で紹介する」

これを最重要ルールとする。読者に「これ知らなかった」「便利そう」と思わせた結果としてリンクがクリックされる設計にする。

## 投稿パターン(4種、ローテーションまたはランダム選択。商品との相性を優先)

| 日本語名 | `post_type`値 | 型 |
|---|---|---|
| 共感型 | `empathy` | 「これ地味に困るよね」→解決策→便利商品 |
| 発見型 | `discovery` | 「こんなのあるの知らなかった」→商品発見→便利な理由 |
| 比較型 | `comparison` | 「○○なら、これとこれどっち?」→違い→おすすめする人 |
| まとめ型 | `summary` | 「知らないと損かもな便利グッズ5選」→複数商品紹介 |

**2026-09-09に旧5パターン(共感投稿/発見投稿/比較投稿/商品紹介/まとめ投稿)から統合した。** 「商品紹介」は独立パターンではなく、上記4パターンいずれの中でも使う共通の投稿構成(上記「投稿構成の基本形」)として扱う。リンクを含めない投稿(悩み共感のみ等)も引き続き可だが、`post_type`は上記4値のいずれかを必ず付ける。

まとめ型で複数商品に触れる場合も、リンクは代表1商品程度に絞る(リンク集のような投稿にはしない)。

## 商品選定基準(11項目、単純な人気順にしない)

`research.py`のスコアは需要・満足度・価格帯の一次フィルタに過ぎない。上位候補の中から実際に書く1件を選ぶときは、以下も満たすものを優先する:

1. 日常の悩みを解決するか
2. 「知らなかった」と思わせられるか
3. Threadsで話題にしやすいか
4. 一目で便利さが伝わるか
5. 季節性があるか
6. SNSで紹介したときにクリックしたくなるか
7. 価格が購入しやすいか
8. レビュー・評価が十分か
9. アフィリエイト対象として利用可能か
10. 競合が多すぎないか
11. 投稿ネタとして継続的に展開できるか

「便利だけど知られていない」商品を優先する。

## 厳守ルール

- **アフィリエイトリンクを含む投稿は、本文の冒頭を必ず【PR】等の広告表示で始める**(景品表示法のステマ規制対応、省略不可)。`publish.py`が投稿時にこの表記の有無・位置を検証し、無ければ投稿を中断する
- リンクを含まない投稿(共感型で商品に触れないケース等)にはPR表記は不要
- **使ったことのない商品について「使ってみた」「効果があった」等の断定的な体験談を書かない**。「気になっている」「レビューを見ると〜という声が多い」など、事実に基づく表現に留める
- 医療・健康効果を断定しない(「絶対に眠れる」等の表現は使わない)
- **節約・お得等の便益も断定しない**。「地味にお金かからない?」のような断定調は避け、「地味に出費かさむよね」のような共感ベースの表現に留める
- スペックは全部載せず3〜4個の重要なメリットに絞る
- 1投稿1商品を基本とする(まとめ型でもリンクは代表1商品に絞る)
- 文字数は**アフィリエイトリンクを含めて**Threadsの制限(500文字)以内(`publish.py`が投稿時に本文末尾へリンクを追記するため、`text`単体の文字数だけでなくリンクの長さも見込んで生成すること)

## 出力フォーマット(`pending/*.json`)

```json
{
  "text": "本文(アフィリエイトリンクを含む場合は【PR】等の表記込みで、冒頭に配置)",
  "affiliate_link": "https://... (楽天またはAmazonのアフィリエイトリンク。リンク無しの投稿はnull)",
  "affiliate_platform": "rakuten|amazon|null",
  "product_name": "商品名(社内管理用、投稿には含めなくてよい)",
  "category": "商品ジャンル(例: キッチン用品。社内管理用)",
  "post_type": "empathy|discovery|comparison|summary"
}
```

Amazonアソシエイトは承認済み(2026-09-09確認)。`amazon-links.md`に実際のリンクが登録されている商品はAmazon優先、未登録なら楽天を使う(現状`amazon-links.md`はまだ空のため、実質的に楽天のみで運用中)。

## 計測するKPI

「いいね数」だけで判断しない。表示数・いいね数・返信数・プロフィール遷移数・リンククリック数・成約数・売上を記録し、**表示→プロフィール遷移→リンククリック→購入**のどこで離脱しているかを見る。詳細と実装状況は `docs/marketing/2026-09-08-threads-post-quality-guidelines.md` 参照。`publish-log.jsonl`のスキーマは`docs/marketing/2026-09-09-threads-account-repositioning.md`参照。
