# 恋愛ジャンルnote 自動化(love-note/)

「note自動公開システム構築指示(2026-08-17)」への対応。オーナーからの依頼「月テーマを決めるだけで毎週自動公開」を、実現可能な形に落とし込んだもの。

## 前提の訂正

note.comには記事公開用の公式APIが存在しない。「note APIキー」は使えないため、ブラウザ自動操作(Playwright)で対応する。

## 全体構成(実際に動く形)

| ステップ | 実行場所 | 自動化レベル |
|---|---|---|
| 1. 月テーマ管理 | このリポジトリ(`monthly_themes.py`) | オーナーが編集する箇所 |
| 2. 記事生成 | クラウド(週次Routine) | **完全自動**(Claudeがテンプレに沿って生成) |
| 3. 下書き保存 | クラウド → `love-note/pending/*.json` | 完全自動 |
| 4. note.comへの公開 | **オーナーのPC**(`publish.py`) | オーナーのPCで実行(手動 or オーナー自身のcron等で自動化可) |
| 5. 公開ログ | `love-note/publish-log.jsonl` | 完全自動(公開実行時に記録) |
| 6. エラー監視 | Claude Code の通知機能 | Slack連携はないため、失敗時はPushNotificationでオーナーに通知する運用にする(必要ならSlack連携を別途検討) |

**なぜ4だけ手動/ローカル実行なのか**: このリポジトリが動くクラウド環境から note.com への通信自体がネットワークポリシーでブロックされている(既存のFocus&Sleep note連携でも同じ壁に当たった実績あり)。クラウドのRoutineが直接note.comに公開することは技術的にできない。

## セットアップ手順(オーナー作業)

1. 恋愛ジャンル専用のnote.comアカウントを作成(`docs/setup-guide/` のガイド参照)
2. 自分のPCに Python + Playwright をインストール: `pip install playwright && playwright install chromium`
3. `python love-note/auth_setup.py` を実行し、開いたブラウザで手動ログイン(初回のみ)
4. 週1回、`python love-note/publish.py` を実行(最初は `--debug` を付けて、実際の画面と処理が合っているか確認すること。note.comの画面構造に合わせてセレクタの調整が必要な可能性が高い)
5. 手間をゼロに近づけたい場合は、オーナー自身のPC/家サーバーでcron・タスクスケジューラに登録すれば、4も自動化できる

## セキュリティ上の扱い

- `storage-state.json`(ログイン済みセッション情報)は `.gitignore` 済み。誰にも渡さない・commitしない
- パスワードそのものはこのスクリプト・Claudeのどこにも渡らない(オーナーがブラウザに直接入力するだけ)
- 詳細は `docs/security/checklist.md` に追記する

## 記事の生成ルール

`article-template.md` 参照。読者投稿を元に記事化する場合は、投稿者の特定情報(本名・SNS ID・学校名等)を書かない/変更し、「投稿を元にしたフィクション/一部再構成」である旨を明記する。
