## ⚠️ 体制について(2026-08-18時点の重要な注記)

このリポジトリとは別に、同じ経営ダッシュボード(Artifact)を共有する**別セッションが実際にnote運用を進めていた**ことが判明した。実際のnote.comアカウント(`https://note.com/unique_condor276`)・X(`@QuietHoursceo`)は向こうのセッションが開設・運用しており、記事も既に**13本前後が公開済み**(正確な本数は未確認、note.com側で要確認)。

このREADME・`drafts/`・投稿キューページは、そのライブ状態を2026-08-18時点で可能な範囲で取り込んで(下記「進捗」参照)最新化した。ただし取り込み元は共有Artifact(ダッシュボード・投稿キューページ)の内容のみで、向こうのセッションの実装コード(note.com/X自動投稿の仕組みなど)には一切アクセスできていない。

**体制**: 専任の note編集部(編集長・ベテラン作家2人・中堅編集者2人・ベテランマーケター・天才作家)で運用する。詳細は `note-articles/TEAM.md`。

## 方針

1. **フォロワー0の間は無料記事+サポート機能のみ。** サポート(投げ銭)機能は既に有効化済み。単発有料記事はいきなり売れない。
2. 週1回更新を目標に、**柱A(睡眠・集中・作業用サウンド)** と **柱B(個人開発・AI経営の裏側)** の2本柱で書く。柱Aは3事業のファンが重なるように、柱Bは個人開発/AI活用に関心がある層を新規に獲得するために書く。
3. ある程度スキ/閲覧が集まった段階(目安: 記事平均スキ数が二桁に乗る、フォロワーが増え始める)で、月額300〜500円の定期購読マガジンへ移行する。**Focus & Sleepジャンルはメンバーシップ企画を進行中**(`note-articles/membership-plan-focus-sleep.md`)。
4. 記事内でBGM動画・アプリへの導線を張り、3事業を回遊させる。
5. トピックは「ノウハウの羅列」より「〇〇してみた失敗談・気づき型」を優先する(`docs/marketing/2026-08-content-topics.md` の調査結果より、この型が最も読まれる)。
6. **アフィリエイト(Amazonアソシエイト/楽天)を導入する。** 記事テーマに関連する商品のみ、記事末尾に自然な形でPR表記付きで掲載する。詳細は `docs/marketing/note-affiliate-guideline.md`。
7. **恋愛ジャンル(ジャンルB)は上記の柱A/柱Bとは別の独立トラックとして運用する**(`note.com/tabun_onaji`、2026-08-18アカウント作成)。オーナー指定の作家が担当し、`love-note/`の自動化基盤で週次生成する。柱A/柱Bの番号付けバックログとは完全に別管理(詳細は下記「ジャンルB(恋愛)の進捗」)。
8. **週次アジャイルサイクルで回す。** 計画→公開→計測(スキ数・閲覧数)→振り返りを毎週繰り返す。

## note運用ポリシー(2026-08-12〜)

オーナー指示により、noteを「記事を作る事業」ではなく「当たりテーマを探す実験」として運用する。

- **投稿目標**: 週3本(オーナーが手動投稿)
- **生成Routine**: 週2回(月・木)。未投稿の下書き在庫が6本を下回った場合のみ、6本になるまで補充する。6本以上ある場合は新規生成をスキップする
- **テーマ管理**: `docs/marketing/2026-08-content-topics.md`のバックログから順に選定し、使用したテーマは`generation-log.json`に記録して再利用を防ぐ。バックログ残り5件を切ったら追加調査する
- **品質チェック**: 生成のたびに以下をAI側で自己チェックしてから下書きとして確定する
  1. 日本語が自然か(機械翻訳調・不自然な語順がないか)
  2. AI特有の紋切り型表現(「〜という発見がありました」の連発など)になっていないか
  3. 内容に具体性があるか(抽象論だけで終わっていないか)
  4. タイトルはクリックしたくなるか(数字・当事者性・意外性のいずれかを含むか)
  5. 読者の悩みに対して明確な価値を提示できているか
  6. 既存記事・下書きとテーマ/切り口が重複していないか
- **Experiment記録**: 記事ごとに`docs/company-os/experiments/note-<記事番号>-<slug>.json`を作成し、テーマ・タイトル・生成日時・公開日時・指標(閲覧数/スキ/コメント/フォロワー増/サポート)を記録する。閲覧数等はAI側から取得できないため、下記「計測(オーナー入力用)」の値をオーナーが更新次第、対応するExperiment JSONにも反映する
- **投稿ステータスの自動検知(2026-08-17〜)**: Claude Codeのクラウドセッションはnote.comへ到達できないため(ネットワーク制限)、GitHub Actions(`.github/workflows/note-publish-check.yml`)が6時間おきにnote.comの公開RSSフィード(`https://note.com/unique_condor276/rss`、ログイン不要の公開情報)を読み、下書き中の記事タイトルと一致するものが公開されていれば`generation-log.json`・各Experiment JSON・`README.md`・投稿キューページのソースを自動で書き換えてコミットする。オーナーがチャットで報告する必要はない。ただし公開中の投稿キューページ(Artifact)自体の再公開はClaude Codeセッションからしかできないため、次にAIがページを触ったタイミングで反映される(データ自体は自動で正しくなる)。仕組みの詳細は`note-articles/note_publish/check_published.py`のdocstringを参照
- **やらないこと(2026-08-12時点)**: note投稿自体の自動化、大規模なパイプライン再構築、新しいAIエージェントの追加、有料記事への移行

## 自動投稿(note_publish/)

note.comには公式APIも投稿用のOAuthも存在しないため(2026-08時点で再確認済み)、`bgm_pipeline`のYouTube/Instagram連携とは違う方式を取っている。ブラウザ自動操作(Playwright)でnote.comに実際にログインし、エディタに直接入力する。**「パスワードを一切預からない」という他の連携の原則からは外れる**ため、詳細は`docs/security/checklist.md`のnote.comセクションに記録している。

### 一度だけ必要なセットアップ(オーナー自身のPCで実行)

Claude Codeのクラウドセッションでは実行できない(ブラウザを見せる画面がない上、このコンテナのネットワークポリシーがnote.comへの直接接続自体をブロックしている)。**必ずオーナー自身の手元のPC**で:

```bash
cd note-articles/note_publish
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium
.venv/bin/python note_auth.py login
```

ブラウザが開いてnote.comのログイン画面が表示されるので、普段通りログインする(パスワードはこのスクリプトには渡らず、note.com自身のページに直接入力する)。ログイン後、ターミナルに戻ってEnterを押すとセッションが`credentials/note_state.json`(gitignore対象)に保存される。以後はこのファイルが再利用される。

### 投稿

```bash
.venv/bin/python publish.py            # 下書きをエディタに入力するだけ(note側で自動下書き保存・未公開)
.venv/bin/python publish.py --publish  # 実際に公開する
.venv/bin/python publish.py --debug    # ブラウザを表示して動作確認
```

**未検証の注意**: このクラウドセッションはnote.comに接続できないため、`publish.py`内のセレクタ(ボタン名やフィールドの識別方法)は実際のログイン画面・エディタでは検証できていない。オーナーが初回実行時、`--debug`で挙動を確認し、必要ならセレクタを調整してほしい。
